# 工程图 CU 提取与证据差异

Python CLI 与本地 Web 审阅台，使用 **Azure Content Understanding GA `2025-11-01`** 对两份原始 PDF
分别进行全页 OCR/layout 提取，再进行有来源约束的语义比较。不是仅凭 LLM 看图总结。
示例配置采用 **`extraction_profile: "layout"` 轻量模式**：CU保留原文、表格和坐标，
工程语义由所选Astra/Luna判断；旧版生成工程字段的模式仍可显式选择 `"engineering"`。
支持 BOM、插头认证印字、线材印字、包装/标签、尺寸公差、备注及图框字段。
本地 Web 另有独立图形候选通道：基于原始PDF渲染和CU布局来源，不额外调用生成模型。
可选**模型语义配对＋CU局部复读**通道：让现有模型先提出跨版本区域对应关系，再高清裁剪复读，
最后只用CU词级原文和坐标生成文字差异候选；原有全页通道仍保留为独立覆盖检查。
文件名/料号不用于推断新旧顺序，必须由调用者指定。

**默认比较设计内容；“显示平移”“显示绘图缩放”两个复选框默认不勾选。**
侧栏的“显示选项与说明”默认收起，点击后可查看复选框和完整说明；收起不会改变已选显示条件，也不会重新调用CU或模型。
勾选后显示对应的可选视图提示和黄色范围框，不计入设计内容变更数量，也不重新调用 CU。
跨位置配对与受约束的对齐仍用于核对内容；移动/缩放同时伴随文字、线条或尺寸标注修改时，
内容候选独立保留，不会因为关闭复选框就整项隐藏。不能可靠配对/对齐时明确待核。

## 隐私与前提

- 只向明确授权的现有 Azure 资源上传输入，不使用第三方解析服务。
  默认仅CU；启用模型比较后还会调用**同一资源、明确配置的现有模型部署**的Azure OpenAI v1接口。
- **客户 PDF、原文、图片、报告、原始响应、凭据不得提交到 GitHub，包括私有仓库。**
  默认 `output\` 和 `local\` 被忽略。建议将实际结果写在仓库外的持久本地目录。
  `.gitignore` 不是安全边界，提交前必须检查暂存内容。
- Azure CLI 已 `az login`，当前身份有 CU 数据平面及自定义 analyzer 创建权限。
  使用内存中的 Entra token，不读取/打印 API key，不保存 token。
- 先确认资源地域、CU `processing_location`（如 `geography`）和模型部署 SKU 的数据边界。
  **资源在某地域不意味着 GlobalStandard 模型处理仅发生在该地域。**
- 只创建有 schema hash 名称的自定义 analyzer；不创建 Azure 资源/模型部署，
  不修改共享 defaults、容量或模型。需在使用前取得该操作的授权。
- `config.example.json` 中 deployment_versions 必须记录实际模型版本和 SKU；
  模型升级后更新它，避免误复用缓存。实际配置存 `local\config.json`，不含密钥。

## 运行（PowerShell）

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -e .
New-Item -ItemType Directory -Force local
Copy-Item config.example.json local\config.json # 填写真实配置

.\.venv\Scripts\python -m cu_diff.cli diagnose --config local\config.json

.\.venv\Scripts\python -m cu_diff.cli extract `
  --config local\config.json `
  --old C:\approved-input\old.pdf --new C:\approved-input\new.pdf `
  --output C:\local-results\drawing-diff --allow-azure-upload

.\.venv\Scripts\python -m cu_diff.cli compare `
  --old C:\local-results\drawing-diff\old.response.json `
  --new C:\local-results\drawing-diff\new.response.json `
  --output C:\local-results\drawing-diff --extraction-profile layout
```

`extract` 保持 OCR 开启，即使 PDF 有少量原生文本；工程图大量文字可能是矢量轮廓。
同一输入 SHA256 + 完整 analyzer + API + 模型映射/版本 + 处理边界缓存已完成结果。
异步操作先保存地址，超时重跑会续查该作业，不会自动重新发起计费请求。
失败作业保留其记录并明确报错；要重新计费尝试，先调查错误，再有意识地移走对应
`cache\*.operation.json`。不能把空结果当成“无变更”。

旧工程字段模式每次请求显式传 `modelDeployments`；轻量模式不配置completion模型，
也不发送该覆盖参数，两者都不修改资源默认映射。响应中的真实 usage、
延迟和 HTTP 状态本地保存；只按实际报告用量与有来源的单价估算费用。CU 提取、contextualization 和
Foundry 模型分别计费，最终金额需以 Azure 账单为准。

旧工程字段模式的CU在创建 analyzer 阶段会验证模型默认映射，早于请求级 override。
因此 analyzer 使用已有 `prebuilt-analyzer-completion` 别名，分析请求将该别名
显式映射到配置指定的模型部署；绝不依赖其可能指向其它模型的资源默认值。
实际所选模型及完整映射保留在 metadata 中，最终 usage 也应核对模型名称。

### 轻量提取与旧模式兼容

`extraction_profile` 只允许 `layout` 或 `engineering`。为兼容已有配置和缓存，
未设置时仍使用旧 `engineering`；新示例配置显式选择 `layout`：

| 能力 | `layout` | `engineering` |
|---|---|---|
| OCR、布局、原文与词坐标 | 保留 | 保留 |
| 详细结果、表格HTML | 保留 | 保留 |
| CU生成工程Items/中文解释 | 不生成 | 保留旧schema |
| CU图形描述/深度图形分析、公式提取 | 关闭 | 保留旧配置 |
| 工程语义配对 | Astra/Luna引用OCR来源 | 原有字段加模型配对 |
| 默认主文字通道 | OCR原文，不伪装成生成字段 | 结构化字段 |
| BOM | 纳入本地表格专项通道 | 保留原字段/BOM通道 |

轻量Web模式要求已批准的 `model_comparison.enabled` 和 `text_pairing` 均为 `true`。
CU只提取不代表整个应用不调用模型；全页模型配对、词级核对、图形复核仍按原预算执行。
局部高清CU也使用轻量分析器，不重复生成整套工程字段。未降低OCR分辨率，不省略
低置信度或未配对证据，也不把LLM建议的坐标伪装成CU词框。
CU未返回图形分区时，本地图形通道仍采用已有整页回退并记录覆盖限制。
轻量模式的区域/局部模型输出schema按本轮两侧CU目录分别约束来源ID。
全局未知或错侧引用仍明确失败；已知来源但超出所属配对组的观察保留显式待核记录，
不自动补配、不执行该组局部/图形确认，也不绘制差异框。原始响应与拒绝原因保留，
其余合规区域及独立全页文字/表格通道可继续分析，不以缺少生成字段作为“无差异”。
轻量模式中将已知图形上下文来源误当文字差异证据的组，也保留明确待核记录，
不把图形描述冒充OCR原文，不绘制差异框；其他合规区域继续，未知/错侧来源仍失败。
全页模型若在同一个区域或观察内重复列出同一来源ID，程序保留首次出现顺序并去重，
记录明确警告及`coverage.coarse.reference_adjustments`，原始模型引用仍保留在
`coverage.coarse.proposed_pairs`和响应缓存中，不为修复格式而重复请求模型。
处理预算与证据合法性分开：超出每侧40条原始引用、每区域20项观察或前40个区域的组，
完整保留为明确待核项，不截断来源、不裁剪、不绘制差异框、不追加模型重试，
其他合规区域继续。即使模型把该大组评为“未变”，也不能跳过复核或让整轮失败。
`coverage.coarse.budget_exceeded_pairs`及各待核项的`budget_issues`记录实际数量和上限。
预算外的每条引用仍须通过未知/错侧检查，也参与跨组占用冲突检查；响应结构和2000项
数组硬安全上限仍严格校验。不能通过重复ID去重绕过原始数量预算。
这不放宽未知/错侧来源、观察所属范围或跨区域占用冲突的校验；
局部词级核对的引用可能影响读序和原文重建，因此仍严格拒绝重复词ID。
局部引用若都是合法来源，但读序颠倒或中间夹有未引用词，只将该条列为显式待核：
逐词保留CU原文及来源，不强行重排、不补词、不拼成确认字段、不绘制差异框。
其余合规条目继续，局部核验状态标为`partial`，原始引用及目录位置记录在
`reference_reviews`/`source_reference_issues`中。未知、错侧或跨条目重复占用来源仍严格拒绝。

两种模式使用不同的不可变分析器和CU缓存身份。切换模式不会把旧重型CU缓存
当成轻量提取的结果，也不会删除它；模型缓存仍按实际输入、提示词、模型版本指纹复用。
首次轻量分析会产生新的提取/模型用量，后续保持缓存开启可复用。候选编号可能随提取模式变化。
改模式后先通过已授权的 `extract` 创建/核对新分析器，再启动Web；Web本身仍不创建分析器。
可将配置改回 `engineering` 回退，不修改Azure共享模型映射或原分析器。
实际速度与Token减少量以当前作业审计为准，不承诺固定秒数或无漏检。

`diagnose` 只读检查 CU 实际 supportedModels 和默认映射，不上传文件。
存在 Azure OpenAI 部署并不等于 CU 支持该模型。`extract` 遇到不支持的模型会在
创建 analyzer/上传文件之前停止；不会偷偷换成其它模型。轻量模式不使用completion模型，
因此不以该模型的支持列表作为OCR提取的前提。

## 模型语义配对与局部复读（可选）

这不是针对某个客户标题、料号或标签的特例。模型读两边全页图像和CU来源目录，按语义提出
规格表、图框、标注、印字等区域的对应关系；字段名不同、移动、换行不要求用固定字符串配对。
文字比较只能引用已给出的CU证据ID；非文字复核可以提出图像搜索范围，
但模型坐标不是最终证据，必须经本地渲染核验。模型不执行工具。

流程为：**全页CU提取 → 模型提出区域配对/疑点 → 原PDF高清裁剪 → CU重新提取词级证据 →
模型核对局部对应 → 本地检查引用/置信度并比较原文 → 原有全页字段、表格、图形覆盖检查**。
局部红框只框CU文字中真正不同的词；纯插入/移除的另一侧仅导航已有上下文，
不把未变的锚点画成变化红框。缺少对应侧、低置信度、裁剪范围不可靠或超预算均是黄色待核项。
模型提出的对应关系仍可能错误，`source_grounded` 只代表有CU来源支撑，不代表工程语义已签核。
模型整体判断“不确定”时可以同时返回有来源的疑点；这些项目始终保留为待核，
即使OCR置信度较高也不升级为已配对文字差异。真正矛盾的“未变但返回变化”等输出仍明确报错。

模型复核建议按子特征区分为**文字差异疑点、图形复核建议、仍存在的标注、尚未解决项**，
每项给出可操作的核查建议。粗比对的黄色框仅使用模型明确引用的变化文字来源；
仍存在的文字、同值标注以及图形上下文不整组高亮。图形建议可描述剖面斜线/填充、
轮廓、孔或线型的外观差异，但不是OCR文字或已验证的像素差异；没有独立定位证据时只导航上下文，
不把附近尺寸框冒充阴影/图形缺失位置，也不据此推断实体部件被删除。
局部复读未发现文字差异时使用 `model_no_text_change`，默认不列入差异候选、不画框，
可在人工复核筛选中查阅限制；若仍有图形观察，则保留图形待核建议。
局部模型的“未变”判断不等于整个区域、编码内容或未覆盖部分已证明一致。

设置 `model_comparison.visual_review: true` 可另外开启**非文字高清复核**，默认关闭以避免
旧配置自动增加模型调用；需要项目的 `[graphics]` 或 `[web]` 依赖。
复用原PDF高清裁剪，由比较模型分别提出同一视图中的独立子特征，
例如左右两处填充应分成两项，而不是把整个部件框起来。每轮默认最多
`max_visual_regions: 2` 个区域（可设1至4），每区额外一次模型请求，不额外调用CU。
调度依据已有LLM的区域判断与来源关系，分为**双侧变化核验、单侧对象搜索、粗判未变的核查建议**，
没有按二维码、标签名称或客户图号写分支。同一优先级先处理单侧候选，避免它一直被双侧裁剪门槛挡住；
双侧与单侧复核共用上述区域预算，不新增无限制模型循环。未执行项明确显示“高清复核未执行”。
粗模型判为未变的图形建议不占高清预算，保留为 `model_visual_context`，默认不列入差异候选，
可以在人工复核筛选中查看；这不证明图形或条码细节完全一致。

**单侧候选**不再要求先找到双侧CU配对：比较模型查看已知侧的整页概览和高清原图，
并在对侧最多 `max_pages_per_side` 页的整页图像与CU目录中搜索移位、缩放或重排后的对应对象。
模型位置须通过页码/坐标校验及原PDF范围内的笔画检查；显示为**黄色对象待核范围**，
不是变化像素残差、CU变化词框或确认新增/删除。仅有笔画不证明模型对象识别正确。
对侧未找到或无法可靠定位时不补框；“所查页面未找到”不是“原图不存在”，
搜索页码、总页数和未覆盖页面显式记录。即使找到对应对象，也保持待核，不能自动升级成变化红框。
该阶段用量单列为“模型 · 单侧对象与对侧搜索”，复用版本化请求缓存。

**双侧候选**保持原有细粒度定位：
已完成局部CU复读时复用词级结果，否则使用全页CU文字来源作保守文字掩膜。
本地用剩余公共轮廓核对受限等比缩放及平移，在原始栅格中测量变化残差，再映射回原页。
整体配准失败时，围绕每个子特征最多尝试3个有界邻域，仍排除所有变化提议区域和文字后
使用相同配准门槛；要求周边锚点有二维分布，且变换与对应搜索范围一致，避免跳到相邻重复图形。
局部通过仅支持该子特征，不证明整幅视图一致；保留整体失败原因、局部窗口与变换、各次尝试供追溯。
只高亮子特征内避开文字的残差包围区域；另一侧没有残差时仅导航对应搜索范围，不虚构变化框。
`model_visual_modified` 表示有局部渲染支撑的图纸填充／轮廓变化候选，
`model_visual_review` 表示执行后仍无法可靠定位；
`model_visual_presence_review` 表示单侧对象与对侧搜索的待核范围；
`model_visual_deferred` 表示预算或来源限制下尚未执行；
`model_visual_no_change` 表示高清模型未提供可定位变化，默认不列入差异候选。
配准失败、模型不确定、文字污染及预算外均保留明确状态，不混成已发现变化。
模型描述不是OCR原文，图形证据没有OCR置信度，也不能推断实体部件被删除。
无法配准、模型仍不确定或尚未执行时，`measurement_status: unmeasured`，残差计数为 `null`，
界面区分定位失败、未执行和仅模型未见变化，不能把未测量显示为零变化。局部栅格重试不增加Azure调用。
图形模型认为未变并不保证视觉差异完整性；图形来源、裁剪映射、实际模型用量和覆盖记录保留在JSON中。

在实际配置中设置 `model_comparison.enabled: true` 才会启用（示例默认关闭，旧配置行为不变）。
默认复用 `completion_model` 指向的现有部署；也可以同时设置
`model_comparison.deployment` 与 `model_comparison.deployment_version`，独立指定同一资源上的
比较模型部署及实际模型版本/SKU。两个字段必须同时填写或同时为空，不自动回退到别的模型。
这不会改变CU提取模型、CU analyzer或既有CU缓存；只改变语义配对/局部核对模型及其请求缓存。
界面分别显示CU模型和比较部署。程序不创建或修改资源、分析器或模型部署。
**直接模型请求遵循该部署的地域/SKU处理边界，不继承CU的 `processing_location` 限制。**
启用前必须确认两者都获批准；GlobalStandard不能当作区域内处理保证。

预算默认：每侧前2页、最多800条可定位来源、每轮最多4个区域对（至多8次局部CU分析、
1次全页模型配对和4次局部模型核对）。裁剪目标400 DPI，单图上限800万像素；
实际DPI记在映射中。支持配置 `max_regions`、`max_pages_per_side`、`max_catalog_entries`、
`crop_dpi`、`max_completion_tokens`，越界配置直接报错。
未覆盖页、未引用来源、模型认为未变的区域和预算外候选均保留覆盖记录，
**不会因模型第一轮没选中就声称没变化**。原有全页通道不按模型建议过滤；
多个通道可能重复，不能相加为独立变更总数。多页截断和区域预算是明确局限，不是完整性保证。

Web启用配置后，`--allow-azure-upload` 同时授权未缓存的全页CU、局部CU及同资源模型请求；
未加该参数仍是只读缓存模式，任一阶段未命中会明确失败，不偷偷跳过。
CLI支持以已有全页CU响应进行同样的模型流程，输入PDF必须已归一化旋转并与metadata哈希一致：

```powershell
.\.venv\Scripts\python -m cu_diff.cli model-compare `
  --config local\config.json --cache-dir C:\local-results\drawing-diff\cache `
  --old C:\approved-input\old.normalized.pdf --new C:\approved-input\new.normalized.pdf `
  --old-response C:\local-results\drawing-diff\old.response.json `
  --old-metadata C:\local-results\drawing-diff\old.metadata.json `
  --new-response C:\local-results\drawing-diff\new.response.json `
  --new-metadata C:\local-results\drawing-diff\new.metadata.json `
  --output C:\local-results\drawing-diff\model --allow-azure-upload
```

`model-comparison.json`/`.zh.md`保留分阶段证据与覆盖，`model-api-events.json`保留真实HTTP记录；
usage来自实际模型/CU响应，配置单价时另行提供费用估算。缓存新增 `model-comparison\`（模型请求哈希、响应和元数据）
及 `model-crops\`（局部PDF与原页坐标映射），均属于客户敏感数据，仅本地保存。
模型缓存键包含请求、图像、schema、提示词、现有部署版本及endpoint；原PDF与裁剪映射也有哈希。
模型失败、拒答、无效引用或截断不能变成“比较成功/无差异”。不自动重发可能已经计费的模型请求；
遇到未决请求记录时先核查，再决定是否移除该条记录并重试。

## 输出与证据

| 文件 | 内容 |
|---|---|
| `old.response.json` / `new.response.json` | 完整 CU 字段、OCR、表格、图形、source/confidence、usage |
| `*.inspection.json` | SHA256、物理页尺寸、原生词/位图/矢量路径数量 |
| `*.metadata.json` | 输入 hash、analyzer/schema、模型版本、操作地址与实际耗时 |
| `api-events.json` | 当前运行的 HTTP 状态、请求 ID、延迟；可能含服务错误，按敏感结果保管 |
| `comparison.json` | 原文与保守标准化值、配对方法、提取/匹配不确定性、覆盖计数、OCR 辅助差异 |
| `comparison.zh.md` | 中文证据差异表；候选与未配对项必须复核 |

一般原文只做空白和 Unicode NFC 比较归一化；合法标题日期空格、表格数量/单位格式
另有严格限定的例外，见后文。保留原始字符，标准号/料号/尺寸不转数字。
唯一功能角色键优先配对，其余默认用保守的文字/坐标候选；启用下述 `text_pairing` 后，
剩余字段/OCR改用LLM来源编号配对，不把变更后的料号作为身份键。
全量 OCR 是独立遗漏检查通道，不能将其与字段差异计数相加。
保留未配对区域、低置信度的“相同”内容和服务警告；高置信度不是正确率保证。
BOM 先以稳定部件描述而不是位置行号配对，避免行重排造成错配。生成的解释文字
不同但原文一致时，单列 `interpretation_only`，不计为原文修改。

### 小字复核

从原始矢量 PDF 重新渲染，不放大已有低分辨率截图。以 PDF pt（左上原点）指定裁剪：


不能只分析预知变更区域。高分辨率裁剪再次提交 CU 属于额外分析，可能新增计费，
应先检查已有缓存并获得授权。本地渲染本身不调用 CU。
现已实现图形残差和子图跨位置配对，但**尚无经标注参考集验证的完整几何检测能力**，
不能将图形候选或生成描述当作已确认的工程变更。

## 分析逻辑详解

### 职责边界与完整流程

CU 负责两份文档各自的提取，不直接给出可信的“旧图对新图最终结论”。
本地代码负责对应关系、比较、证据坐标和候选分类；人工负责确认实际工程意义。
当前并非任意部件的语义识别器，也没有实现完整的“物体—类型—关系”图谱。
以下流程对应 Web；`cli compare` 只比较已提取字段/OCR，
`cli graphics` 则独立运行本地图形比较，`cli tables` 结合原PDF和已验证CU缓存补充非BOM表格证据；
三者的输出范围不能混淆。

| 阶段 | 实际处理 | 必须保留的证据或约束 |
|---|---|---|
| 输入与身份 | 显式指定 old/new；检查 PDF、页数、hash，生成即时预览 | 原件只读；不由文件名、料号判断时间顺序 |
| 坐标准备 | 检查页尺寸和旋转；Web 必要时生成外观保持的分析副本 | 原件 hash 与分析副本 hash 分开记录；不能只凭宽高相同复用坐标 |
| 全页提取 | 分别对完整 PDF 获取 OCR、layout、表格、图形区域和领域字段 | 优先缓存；保留完整响应、原文、source、confidence 和警告 |
| 文本配对 | BOM 角色、唯一字段键、受限文字/坐标候选；另做 OCR 行检查 | 提取置信度与配对确定性分开；未配对不自动成为增删 |
| 列级细化 | 把 BOM 字段关联到同侧实际表格行，按表头角色对齐列 | 列文字须与结构化行文字相符；仅变化列提供差异框 |
| 非BOM表格 | 结合PDF网格和已有CU文字，核对规格/修订等表格的单元格、列及网格结构 | 对应依据、网格测量与OCR内容分开记录；缺失列不伪造对侧位置 |
| 本地图形 | 配对父图形区、拆分子图、跨位置匹配、受约束对齐与残差比较 | 原 PDF 渲染、可追溯坐标；不额外调用生成模型 |
| 审阅与输出 | 显示两侧实际来源、设计内容候选、未配对与覆盖限制 | 平移/绘图缩放默认隐藏，可分别勾选；可选提示不计内容变更 |

这与“渲染/OCR → 分段 → 对齐 → 理解 → 配对 → 分通道比较 → 验证”的讨论思路一致，
但当前分段仅包括 CU 字段、OCR 行、表格单元格和局部轮廓子图，
不能声称已完成任意图纸的语义原子化。

### 为什么有原生 PDF 文本仍必须 OCR

工程图可能由大量矢量路径组成：看起来像文字，但字体已转成轮廓，原生文本接口只提取出
页码等少量字符。也可能没有任何内嵌位图，但依然需要渲染后识别文字。
因此“能提取出几个词”或“没有图片”均不能成为关闭 OCR 的依据。
细小印字应从原始矢量 PDF 重新渲染复核，不能靠放大低清截图恢复不存在的细节。
OCR 遗漏仍可能影响文本比较和后续图形中的文字掩膜。

### 字段、OCR 与 BOM 怎样建立对应

字段同时保留 `RawText`（提取原文）、`Detail`（生成解释）、类别、区域、键和来源。
一般字段优先采用两侧唯一的 `region + category + key`；重复键不强行一一对应。
BOM 更早采用同区域中唯一的部件描述/角色，重复描述可用唯一且完全一致的行内容消歧，
避免把位置行号或可能变化的料号当成不变的身份。
这里的“角色”来自提取文字的受限解析，不是独立的语义零件检测。

已知类别名称忽略大小写进行配对，同时在 `raw_category` 和原始 schema 中保留原值，
避免 `bom` / `BOM` 这种提取格式差异造成漏配。图框中的印刷 `P/N:` / `Part Number:`
标签另做保守的标签—值关联：旧侧拆成两项、新侧合成一项时，按唯一的印刷角色建立对应，
不是按料号值猜测身份。合并项必须找到有实际来源的唯一 OCR 值行；拆分项必须有唯一的
近邻值及一致的页面证据。原分组保存在 `schema_sources`，只框完整的实际值文字。
重复标签、多个候选、无法定位或不在标题栏范围时不强配；此规则不是任意字段拆并。

稳定键不能配对且未启用 `text_pairing` 时，只在同类别、同 content 范围考虑候选：
有效单一来源框的 IoU（交并比）≥0.65 且文字相似度≥0.55，或同区域非空文字完全一致。
候选必须互为最佳，并在有竞争者时两侧均领先次佳至少0.15；这类回退对应仍标为不确定。
**多个来源多边形不能直接拿一个猜测的大框套用单框几何回退。**
所以两边肉眼相似的字母组，仍可能因分组、生成键或 OCR 字符不同而保持未配对；
这不等于新图新增了该内容。

OCR 是独立的遗漏检查通道，先找同页原文相同的唯一对应，再检查连续2～8行
能否与另一侧一行完全拼接一致。拆并还需阅读顺序、距离、左边界和来源重叠满足约束，
结果为 `reconciled`，而非一次内容修改。它不是任意段落的智能拆并。
剩余行再做保守的几何/文字配对；重复文字或无法定位的内容继续待核。
默认不把字段差异与 OCR 差异相加，以免同一内容重复计数。

BOM 行配对成功后，还必须通过 `table_diff.py` 的单元格核验：
一侧的整行文字与实际表格行吻合，两侧列按表头含义对应，而不是按第几列对应。
例如合成场景中一行包含品名、数量、单位、料号、材料和厂商，只有料号与厂商变化时，
只框这两列。数量与单位在一侧合列、另一侧拆列，不应导致整行或单位列误报。
证据冲突时显示“无法细化”，不再用整行红框伪装列级结果。

表头也可能位于表底、且被 CU 标成普通 `content` 单元格。除显式列头外，本地识别
严格的已知 BOM 列组合（如 `ITEM / DESCRIPTION / Q'TY / U/M`），再校验单元格网格和来源。
两张完整提取表格须有共同部件行锚点才能建立对应，不能只凭表格序号、行号或生成的键。
在可靠对应范围内，未匹配的行输出 `table_row_added` / `table_row_removed` **候选**，
默认“设计差异候选”中可见；它们与普通未配对字段分开计数。新增/删除行只在实际有来源的一侧
画红框，对侧通过独立 `table_context` 导航到整张对应表，不伪造缺失行位置。
表格结构完整不代表 OCR 内容无遗漏，仍需两侧原图确认；缺表、缺格、来源或对应关系不可靠时
不会升级为行增删。图外标注与表内行不能仅凭同名文字去重。

### 表格专项通道

仅修复 BOM 并不覆盖全部表格：规格表可能没有进入 CU 的 `tables`，
只有表头和分散的文字行；修订表也可能漏掉没有文字的空白行。
Web 因此增加独立的“表格专项证据”通道，默认与字段和图形候选一起显示，
使用原PDF的本地网格证据和已有CU文字，不重新调用CU。
旧模式默认排除已由字段通道处理的BOM；轻量Web模式显式包含BOM。
独立CLI使用 `tables --include-bom` 开启相同覆盖。
`table_cell_modified` 表示有来源的单元格文字不同；
`table_column_added` / `table_column_removed` 表示对应网格的列差异候选；
`table_grid_changed` 则是实际绘制的网格结构不同，**包括表头与空白行，不能称为业务记录增删**。
没有充分来源或对应依据的区域保留诊断，不按“没有结果”宣称没有变化。
缺失侧仅用 `table_context` 导航，不画推测的缺失单元格。
这些证据可能与结构化字段、OCR或图形通道重复，不能将所有通道条数相加作为独立工程变更数。

无界面复现时，输入PDF必须与CU metadata的 `document_sha256` 一致：
若CU分析的是旋转归一化副本，应传该副本，而不是未经验证的同名原件。

```powershell
.\.venv\Scripts\python -m cu_diff.cli tables `
  --old C:\local-results\old-analysis.pdf --new C:\local-results\new-analysis.pdf `
  --old-response C:\local-results\old.response.json --old-metadata C:\local-results\old.metadata.json `
  --new-response C:\local-results\new.response.json --new-metadata C:\local-results\new.metadata.json `
  --output C:\local-results\tables
```

本地输出 `tables.json`（完整来源、覆盖诊断）与 `tables.zh.md`（中文证据表）。
原生文字、矢量轮廓文字和位图的逐区域来源分类仍不是本demo的输出；
网格检测也不意味着已实现任意版式的通用表格识别。

单列印字面板另按唯一印刷标题配对，正文跨行拼接后比较；相同文字仅重排为不同的行数，
不报内容修改。整段OCR不完整时，仅能对独立通过来源核验的唯一锚定文字片段给出候选，
并保留完整OCR行上下文、行数和其余未解决问题；局部片段的 `complete` 不代表整段完整。
表格、列和面板项目的 `table_comparison.scope` 明确限定核验范围。
网格提取限完整的直线描边/细填充线框；部分格线、合并格、位图网格及模糊表头不保证覆盖。
表头配对至少有三个共同且唯一的识别列，并覆盖较多列一侧的60%；单列印字面板使用单独的标题门槛。
字段的低OCR置信度、重复重叠的符号和未被OCR解释的墨迹必须保留为复核问题，不更正或猜测数字。

另外，对“BOM同一项目文字未变，但图外同名标注的提取次数不同”增加
`annotation_occurrence_changed`。仅当唯一BOM角色、两侧表内同名OCR和图外来源能明确区分时，
才默认展示为**黄色待核证据**，不计为已配对文字修改。缺失侧只导航未变的BOM行作为上下文，
不把表内文字冒充图外对应项，不认定实际标签或部件被删除；普通未配对项仍不升级。

### 非文字部件怎样比较，为什么以前漏掉交换

CU 的一个 `figure` 可能包含多个视图、局部放大图、引线和文字，而不是一个部件。
旧的区域比较只估计一组平移：若区域内两个视图分别向相反方向移动，
不可能用同一个平移量同时对齐。出现大面积像素残差或 `visual_uncertain`，
并不表示系统已识别出两个视图交换。

当前增加了子图层。以**合成示例**说明：旧图从左到右是视图 A、B，新图是 B、A。
算法先分别寻找具有可分辨轮廓和内部特征的子图，再比较 A 与各新图候选的外观，
建立旧 A→新 A、旧 B→新 B；不按“旧左→新左”强配。
对应关系唯一时，按各自视图的局部坐标比较内容，而不是比较原纸面位置。
位置变化不计设计内容差异。A、B 只交换位置而内容不变时，默认不产生差异列表项或框；
勾选“显示平移”后，才显示可选位置提示和对应视图范围，不把它们称为内容残差。

“隐藏位置/绘图缩放提示”与“确认内容相同”是两件事：不能直接过滤掉所有
`drawing_size_changed` 条目。必须先核对对应视图，在受约束的对齐后继续比较内容；
不以任意仿射、非等比拉伸或弹性形变消除真实形状差异。
子图移动后仍可能有轮廓和标注变化。独立对齐成功后，用子图残差替代父区相同位置的残差；
未覆盖的父区和未可靠对齐的子图仍留待复核，不因找到交换视图就忽略其余内容。
重复或极相似视图不会以位置强行打破平局，无法确认对应时保留待核，而非宣称设计内容一致。
详细阈值及对应实现见后文“图形算法与阈值”。

### 如何解释结果和框

| 分类 | 表示什么 | 不表示什么 |
|---|---|---|
| `modified` | 已配对提取原文不同；BOM 可细化到变化列 | 不是排除了 OCR 错误的工程结论 |
| `relocated` | BOM 角色配对后的印刷行号变化 | 不是纸面几何位移，也不是自动认定替换了部件 |
| `formatting_only` | 合法标题日期空格，或表格列值一致的限定格式差异 | 不是忽略任意空格、标点或尺寸字符 |
| `interpretation_only` | 原文相同但生成解释/身份标签不同 | 不是图纸原文改变 |
| `reconciled` | 满足约束的 OCR 行拆并对应 | 不是新增或删除文字 |
| `unpaired_old` / `unpaired_new` | 本侧有证据，尚未可靠找到另一侧对应 | 不是确认删除/新增，也不是另一侧没有该内容 |
| `visual_moved` | 可选纸面平移提示（包括交换位置），默认隐藏 | 不是实物移动或内容修改；勾选后仍不计内容变更 |
| `visual_scaled` | 可选绘图缩放提示，默认隐藏 | 不等于实物尺寸变化，也不能据此认定内容一致 |
| `visual_modified` | 局部墨迹/线条外观残差候选 | 不能推断材料、工艺、功能或真实尺寸 |
| `visual_annotation` | 落在 CU 文字位置掩膜内的残差候选 | 不是可靠的文字语义分类；OCR 掩膜也可能不完整 |
| `visual_uncertain` | 对齐未可靠接受，像素差异只供复核 | 既不是确认修改，也不是“没有变化” |

默认绘制内容证据框，来自文字/单元格来源或实际残差像素。
勾选平移/绘图缩放时额外使用黄色虚框标记对应视图范围，明确区分于内容残差红框。
`context_locations` 仅供导航，不自动画成差异框。
仅一侧有残差框且配准已接受时，将残差位置按同一平移/等比缩放映射到另一侧，
两边可同时定位：实际残差用红色实框，对侧用标注“对应”的红色虚框。
对侧映射单独记录为 `counterpart_locations`，**不是本侧实测残差**，不增加变化像素或条目数。
未配对、未可靠对齐、来源裁切原点缺失或映射完全在页外时不猜测对应框。
提取 `confidence`、对应 `match.certainty`、启发式 `score` 与配准是否接受是不同信息；
图形没有概率置信度，不把匹配得分换算成“准确率”。
`D...`、`G...` 是当前结果中的显示编号，不是跨版本稳定的部件标识；
新增检测层后编号可能变化，复核应同时保存两侧 hash、原文/位置及配对元数据。

### 讨论中的问题与修正（脱敏归纳）

| 观察到的问题 | 原因 | 当前处理及尚存限制 |
|---|---|---|
| 两侧看起来一样，却显示差异 | OCR 字符/分组或生成键不同；未配对项曾容易被误读为新增 | 未配对单列待核，不凭肉眼相似强行配对；保留两侧独立证据 |
| 怀疑比较了同一份文件 | 相似版式和联动定位不足以证明文件身份 | 显示原件 SHA256、前后端拒绝相同字节、核对返回文档 ID/hash；不同 hash 也不证明每处内容不同 |
| 日期只是间隔不同也报修改 | 纯字符串比较把日期分隔符附近空格当作内容差异 | 仅对明确标题日期字段中的合法日期做限定格式归类 |
| BOM 只有几列变化却整行标红 | 结构化提取的证据粒度是整行，且两侧分列方式可能不同 | 用实际表格 source 做列级细化；无可靠单元格证据则不退回整行红框 |
| 包装图的非文字线条变化遗漏 | 仅字段/OCR 比较没有真正比较图形墨迹 | 增加本地残差、文字掩膜和矩形左缘长线规则；规则不能解释工艺含义 |
| 组合图里视图交换导致错误对应 | 父区域只有一组平移，无法解释相反方向的子图移动 | 子图跨位置匹配后比较内容；交换仅作为默认关闭的平移提示 |
| 示意视图缩放后整个轮廓被标红 | 只做平移会保留绘图比例带来的残差 | 可靠对应后受约束地核对缩放；缩放提示单独勾选，真实内容残差不随开关隐藏 |
| 旋转图纸重上传时缓存或框不一致 | 原件和规范化副本字节不同；尺寸相同不证明坐标等价 | 原件 hash 优先查缓存，加几何与渲染外观核验；副本保存不生成随机 PDF ID |
| 后端未接入图形能力，前端却有入口 | 静态界面与后端功能状态不同步 | 仅在 `graphics_enabled === true` 时启用；缺失/false 明确不可用，不产生假候选 |

上述修正针对根因，不能据此承诺所有误报已消失。
例如日期格式修正不解决任意 OCR 错字；长线检测不等于完整形状理解；
子图跨位置匹配也不等于能够识别所有语义部件。

### 换成其他两份文档是否适用

这是可复用的工程图对比框架，不依赖客户文件名、真实料号或预先指定的变更坐标；
最适合具有相近版式、明确新旧关系的工程图修订比较。
任意两份无关文档虽然可通过格式校验，但未必存在合理对应，不应把大量未配对当作有效差异报告。

| 输入情况 | 预期表现与边界 |
|---|---|
| 同类图纸的文字、BOM、包装和独立视图修订 | 可复用现有提取与比较链路；仍需人工确认 |
| 大幅改版、图形跨父区移动或页面重排 | 父区按同物理页配对；不保证建立跨区/跨页对应 |
| 扫描图、低分辨率、浅灰细线、遮挡或粘连视图 | 分段、OCR 和残差质量可能下降，可能漏检或出现更多待核项 |
| 任意旋转的单个零件、复杂拓扑或需要判断材料/功能 | 未实现相应语义/几何推理；页面 `/Rotate` 规范化不等于零件旋转识别 |
| 重复且外观相同的多个视图交换 | 图像不足以建立唯一身份，保留不确定性，不强行判定交换 |

更换成未缓存的文档，授权上传模式下会触发新的 CU 分析并可能计费；
只读缓存模式则明确失败。纯本地图形 CLI 不需要 CU，但没有 CU 布局/文字位置时
会回退全页，且不能同样可靠地区分文字标注与非文字外观。

### 字段 / OCR 的 LLM 语义配对（可选）

当同一参数的文字框发生位移、数值改变或CU生成了不同字段名时，文字相似度加框重叠阈值可能
留下两条未配对记录。可在已批准模型部署的 `model_comparison` 中同时设置
`"enabled": true`、`"text_pairing": true`，启用**语义对应 → 来源校验 → 原文比较 → CU变化词定位**。
`text_pairing` 默认关闭，不改变旧配置及离线 `compare` 命令；启用时不再使用
`geometry_text` 来配对变化文字，稳定身份与完全相同文本的已有安全配对仍保留。

每轮至多增加**一个批量模型请求**：发送仍未配对的字段/OCR来源目录、局部上下文和限页预览。
模型只能引用现有旧/新来源编号，不能生成原文、坐标，不能把已匹配上下文当成候选。
程序检查编号归属、通道、重复占用及有限的拆行/合行；支持的对应直接替换D/字段/OCR中的
未配对记录，**不是只添加一个M建议**。不确定的对应继续保留待核，非法输出明确失败，不回退成成功结果。
无需旧、新文字框重叠，但模型提出对应不等于工程事实确认。

模型列出多个来源编号时，程序仍须验证它们能否安全拆并。编号排列可按已有CU读序规范化，
但不能因此把跨区域或夹杂独立行的文字强行合并；这些组保留原始未配对记录、黄色待核证据和
明确原因，其余合法对应继续处理，整体语义覆盖标为部分完成。未知编号、跨通道引用、
重复占用来源或不合法的响应结构仍会让整个批次校验失败，不当作普通待核吞掉。

框使用现有CU的实际 `words` 多边形；先核对词与原始来源的关联和完整重建，再只框不同的词。
例如**合成**参数 `Q=4.50±0.2 → Q=5.75±0.2`，仅当CU确实分别给出这些词时框 `4.50`、`5.75`，
不框未变的参数名和公差；绝不按字符宽度估算边界。CU词缺失、歧义、低置信度或映射不合法时，
保留原文和导航上下文，明确定位不足，不以整行红框冒充精确定位。

`max_text_pairing_entries` 默认300（范围20–800），共享 `max_pages_per_side` 页数上限。
预算遗漏、无可定位来源、模型未引用和不确定建议分别记录在 `coverage.semantic_text`；
一批最多80组、每侧每组最多4条。达到预算不会声称整图比较完整。字段与OCR可能重复，不可叠加为独立变更数。
请求使用既有批准的比较模型、专用缓存与 `model_text_pairing` 用量阶段，不额外调用CU；
重复运行优先复用缓存。缓存未命中时仍需 `--allow-azure-upload`，不能用缓存模式偷偷发请求。
Web详情展示语义对应、CU变化词和定位限制，PDF导出保留当前词框和简短变化内容；
CLI `model-compare` 额外写出 `text-comparison.json` 和 `text-comparison.zh.md`。

## 本地 Web 工程图审阅台（不部署）

```powershell
.\.venv\Scripts\python -m pip install -e ".[web]"
.\.venv\Scripts\python -m cu_diff.web --config local\config.json `
  --data-dir C:\local-results\web-sessions `
  --cache-dir C:\local-results\drawing-diff\cache `
  --port 8765 --allow-azure-upload
```

在浏览器打开 **http://127.0.0.1:8765**。服务只绑定 `127.0.0.1`，不创建云资源，
不执行部署，也不允许网页请求创建 analyzer。必须先有与当前 schema 匹配的现有分析器；
若缺失，按已授权的 CLI 初始化流程处理，Web 会明确失败而非修改 Azure 配置。
配置和 Entra 凭据仅在服务端。页面不访问外部 CDN、字体或分析服务。

**操作：** 分别上传“原图”“调整图”，即可查看本地渲染预览，不等待 CU。
仅支持内容有效、未加密的 PDF，单份最大 **20MB / 20物理页**。页码切换、缩放和
适应宽度只影响视图；原→新顺序始终由用户上传角色决定。点击“开始对比”后异步执行
现有 CU/缓存/配对及本地图形流水线，展示排队、提取、配对、图形比较、成功或失败状态。
Web依赖包含NumPy和OpenCV headless，建议使用独立 `.venv`，不要改动共享Python环境。

**上下窗口大小：** 按住图纸与详情之间的横向调节条上下拖动，可调整图纸和下方面板的高度，
适用于证据、耗时和费用三个标签页。上下两区保留可用的最小高度；窗口变小时自动限制范围，
不改变证据坐标或触发分析。支持触控拖动，键盘上下方向键微调，Shift 加大步长，
Home/End 调至详情最小/最大高度；Escape 取消本次拖动，双击调节条恢复默认高度。

**右上角分析设置：**
- **缓存默认关闭**：本轮不读取历史CU与模型分析缓存；
  可能重新产生CU及模型费用；不会删除旧缓存或绕过未决请求的防重复计费保护。
  只读缓存服务不能关闭缓存，也不能用该开关代替 `--allow-azure-upload` 授权。
- **分析模型默认 GPT-6 Sol**：从服务端批准的部署列表选择 GPT-6 Sol / GPT-6 Astra / GPT-6 Luna。
  只影响直接模型对比、局部核对和语义配对，**不会改变CU提取模型**。
  切换模型可能没有对应模型的缓存，不应期待复用另一模型的推理结果。
  手动开启缓存后才优先复用同一模型的历史结果；刷新页面恢复服务端默认设置。
- 设置在提交时固定，分析期间锁定；修改已完成任务之后的选项只影响下一次对比，
  不会把原结果、Token或费用重新标成另一个模型的结果。仅切换选项不会发送分析请求。

服务端通过 `model_comparison.models` 列出
`{id, label, deployment, deployment_version}`，用 `model_comparison.default_model` 指定默认ID。
部署版本必须填写已核实的 `模型名:版本:SKU`；浏览器只提交允许的ID，不能指定任意部署或版本。
旧配置未提供列表时保留原部署行为。新增可选部署不会改变CU缓存身份，Astra原有响应缓存仍可复用。
GPT-6 Luna 可使用明确标记来源的用户配置单价；示例已提供下述用户报价。
Sol未配置适用价格时保留真实Token并显示费用待核，不套用Luna、GPT-5.6 Sol或Astra价格。
其他模型未配置适用价格时同样不推算费用。既有配置中的显式默认模型仍按配置执行。

关闭缓存的任务将新响应、裁剪及防重复提交标记写入独立的
`cache\uncached-jobs\<job_id>`，只在本轮内复用完全相同的请求。
这些目录持久保留，不自动过期或合并回共享缓存；后来开启缓存的任务也不会搜索这些隔离目录。
它们同样是敏感本地产物；清理前先核对未决提交，不能通过删除标记自动重试可能已计费的请求。

**并行提速（不减少核验覆盖）：** 默认 `performance.cu_workers: 2`，原图/调整图的全页CU
同时提取；每个高清复读区域的两侧CU也同时进行。模型细核仍等待两侧来源齐全后才执行，
局部区域预算、分辨率、原文/来源核验和模型请求内容不变，不通过少看区域换取速度。
PDF渲染、裁剪与目录组装仍在协调线程完成，不在线程间并发操作PyMuPDF。
每轮最多两个CU任务；同一缓存键加锁去重，失败后等待已在途的另一侧完成并记录实际用量，
不自动重试可能已计费的请求，不把部分结果伪装成完整结果。CLI提取也使用同一双侧调度。
如部署吞吐量不足或频繁限流，将 `performance.cu_workers` 设为 `1` 可恢复串行，
不影响已有缓存；只允许1或2，不会自动增配云资源。自定义客户端未提供线程安全上下文接口时保持串行。
并行主要减少等待，**不承诺降低Token或CU费用**；复用历史结果仍应保持缓存开启。

文件标题显示上传原件的 SHA256 摘要（悬停查看完整值），覆盖面板保留完整原件及
CU分析文件hash。两侧字节相同会在前后端阻止对比，避免无意义CU调用；不同hash仅证明
文件字节不同，不证明每处画面不同。前端接收结果时核对两侧文件ID和hash，拒绝错源结果。

默认显示结构化字段和图形候选，不把独立OCR辅助通道重复计入。已配对的原文差异、
印刷行号变化和图形内容候选使用红框。两个独立复选框默认不勾选：
“显示平移（含视图交换）”“显示绘图缩放（非实物尺寸）”；选中后可在当前通道/
复核筛选范围内显示可选条目及黄色视图范围框，取消后同时清除相应列表、框和选中详情。
开关仅过滤已经返回的本地结果，不提交新任务、不产生新 CU 调用。状态栏将可选提示数量
与设计内容候选数量分开，缺少图形能力时禁用两个选项。
忽略的是纸面排版提示，不是忽略料号、尺寸、数量、印刷行号或标注原文的实际变化。
选择一项会定位到各侧证据所在物理页。
同一项可有多个源区域；字段使用CU原页坐标，图形使用本地渲染坐标回映射，两种来源明确区分。
实际残差框只来自本侧证据；可靠单侧图形残差另提供对侧映射的红色虚框，
点击后两侧定位到同一个局部位置，而不是只定位整个视图。
没有来源、未知单位、
页尺寸不符、越界坐标会明确提示“无法定位”，不根据文字推测位置。
未配对项保留在“未配对待复核”范围，不混入默认差异索引；显式查看时使用黄色虚框，
详情提示“未配对到证据不代表原图没有”，不认定增删，也不为了成对显示而猜测另一侧框。
解释不同、一致项复核和OCR分段合并同样使用黄色虚框，不作为原文变更。选择“全部证据”
并勾选“显示仅解释差异”可查看生成解释；解释不同不计为原文差异。
低置信度、OCR辅助通道、未配对及覆盖限制需人工审阅，不能宣称完整几何变更检测。

### 导出当前对比到PDF（本地，不重新分析）

完成对比、两侧预览载入后，可点击顶部“导出 PDF”。导出以**点击时**的证据通道、
复核范围和三个显示开关为准，不会把隐藏候选重新加入，也不会只导出当前选中的一条。

- 首页左右并排显示当前各自选择的**完整物理页**，不是只截取缩放/滚动窗口。
  从本地PDF保持清晰的页面内容；有批注或表单控件时使用包含其外观的本地渲染。
  保留当时SVG中实际显示的框、标签、颜色、透明度、实/虚线及选中强调，
  按各侧页面实际显示区域映射，不按外层容器猜测坐标。没有来源的一侧不补框。
- 后续页面按当前索引顺序精简为“候选编号 + 标题 + 一条说明”。
  模型项直接保留已有的“模型理由（非原文证据）”，不另调模型总结；非文字项优先采用
  该子特征自己的模型描述，定位未解决时仍标明待复核。其它通道保留变化列或旧新值的简述。
  不再逐项打印重复提示、坐标、来源JSON及内部检测参数；完整证据仍在网页详情中保留。
  多个候选连续排版，按实际内容分页，不再每项独占一页；书签定位到对应条目。
  列表中位于其它物理页的条目也保留简述，但不伪装成当前总览页的框。
- 红色实框、红色对侧映射虚框与黄色复核框保持区别；映射框不是本侧实测变化，
  填充/轮廓候选不表示实体部件删除。空筛选可导出，但不宣称整份图纸没有差异。

这是已有对比的界面快照，不重新调用CU、模型或重新定位；导出操作不新增上述分析费用。
下载文件包含客户图纸与提取内容，应按敏感客户产物保管，禁止提交Git。
服务在本地内存中生成并返回PDF，不覆盖原件，不把任意客户端路径或HTML作为文件/资源加载。
导出受会话、CSRF、作业、文件版本和ID/hash校验保护；文件更换或结果失效后拒绝旧证据导出。
上传替换会取消浏览器中的未完成下载；导出过程中切换显示条件不改变已捕获的快照。
未完成对比、预览未载入时按钮禁用；内容超过导出上限时明确报错，不悄悄删减详情。

### 本地图形候选（不新增CU分析）

这里的“不新增”仅指本地 `compare_graphics` 阶段；完整 Web 作业之前的 CU 提取
是否新增计费，取决于授权模式和缓存是否命中。

1. 处理整份原始PDF各物理页。优先使用全页CU返回的全部图形来源区域，
   按区域重叠和所引用的原始文字锚点做双向唯一配对，不用生成的图形描述判定变化。
   某页一侧没有可用图形区域时，两侧都回退到该页全幅扫描，明确记录覆盖方式。
2. 在相同物理尺度以默认200dpi灰度渲染，每页最多800万像素；页面大时共同降低DPI，
   不通过各侧独立降采样制造尺寸差异。对复合区域增加
   **封闭轮廓子图拆分 → 跨位置外观配对 → 受约束独立对齐与残差**：
   使用轮廓和内部墨迹建立指纹，不按原位置强制对应。双向最佳匹配须得分≥0.80，
   且两侧均比次佳高≥0.06；这些是启发式阈值，不是准确率。
   可靠对应后允许满足门槛的**等比绘图缩放＋平移**，不做非等比拉伸、仿射或弹性变形。
   残差回映射到各自原页坐标，不把归一化画布当原始来源，也不修改 PDF。
   可建立旧左→新右、旧右→新左的对应视图；对齐后仍存在的内容残差默认保留。
   平移/绘图缩放提示独立输出供复选框显示，不因变换被识别就过滤整个视图的内容。
   重复或无法唯一匹配的视图保留父区域复核，不强行确认交换，也不认定新增/删除。
3. 唯一的大矩形轮廓可作为平移基准，其绘图宽高比变化仍保留。附着引线不要求
   整个连通轮廓仍是四边形，而是校验实际四条直边。矩形左缘长竖线可进一步统计，
   只框未配对的实际线条；不把线数直接解释成封口工艺、材料或实物结构。
4. 对齐后比较各侧实际墨迹残差，抑制小范围锯齿噪声；CU文字位置用于分离含文字
   的标注候选。实际出现残差的一侧画红色实框；可靠配准下将该局部框映射到空侧，
   用红色虚框标明对应位置，不伪装成本侧变化像素。无法可靠映射时仍仅导航上下文。
   纯平移/可靠等比绘图缩放不计内容变化；非等比变形和未能解释的墨迹仍保留，
   实物尺寸是否改变以尺寸标注等证据为准，不以示意图大小判断。
5. 缺少可靠对应关系或不能对齐的复杂组合图保留 `visual_uncertain`，仅供复核，
   不假装完成了语义部件识别。成功独立对齐的子图用其局部残差替代父区相同位置的残差；
   其余父区域仍比较，不因找到两幅子图而忽略其他内容。
   旧侧子图外14pt上下文映射到新侧（接受缩放时为14pt乘以该比例），仅消除能按
   同一已接受变换对应的墨迹，避免随视图移动/缩放的不变标签重复误报；
   其他候选轮廓受保护，无法对应的文字和线条仍保留为残差。
   每侧每类最多显示24个残差区域，未显示数量和阈值明确记录。
   每父区最多24个子图候选；超限则跳过该区子图配对，避免截断制造“唯一匹配”。
   子图最小边长14pt，开口/相连轮廓、过小图形、外观近似视图及跨父区/跨页移动仍可能漏检。

图形编号 `G...` 与字段编号 `D...` 分开。详情记录渲染DPI、对齐方法、
变化像素数、归一化原页坐标和限制。匹配分数不是正确率；外观残差框是变化像素的包围区域，
不代表框内所有内容改变。可选平移/绘图缩放条目显示纸面变换诊断与黄色视图范围框，
不是内容残差，也不表示框内所有内容都改变。
细小/浅灰标记、图形分组错误、页面重排可能漏检，
也不解码条码内容。尺寸标注数值应继续与字段证据结合，不能由示意图宽高推断实物尺寸。
浏览器只有收到后端 `graphics_enabled=true` 才启用图形入口；旧后端缺少此字段时
明确显示未启用，不产生假候选。图形阶段异常会使本轮任务明确失败。

#### 图形算法与阈值

当前方法版本为 `local-graphics-v5`，输出 `comparison_policy=design_content_only`。
该策略针对内容比较；`transformations_included` 说明是否另行返回可选排版提示。
以下数值来自实现，用于说明误差容忍和候选选择，
不是经客户参考集校准的精度指标，也不代表已有同名配置项可直接修改。

| 层次 | 当前规则 | 取舍 |
|---|---|---|
| 父区域来源 | CU 全页提取的 figure source；使用引用段落的原文字面锚点，不使用生成描述 | CU figure 不是语义部件；一侧无有效区域或区域数超过32时，两侧同页回退全幅 |
| 父区域配对 | IoU≥0.2，或文字词项 Jaccard≥0.7 且共享至少3个词项；分数为0.65×IoU＋0.35×Jaccard；双向最佳、次佳差值≥0.12 | 不仅按位置，但仍依赖父区对应；子图不会任意跨父区搜索 |
| 同尺度渲染 | 默认200dpi，允许96～300dpi；每页上限800万像素，两侧共同降采样；灰度值＜180为墨迹 | 大页实际 DPI 可能低于请求值；细浅线可能遗漏 |
| 子图候选 | 小尺度闭运算后提取层级轮廓；最小边长14pt；轮廓面积/包围框面积≥0.25；框面积≤父区域比较栅格60%；排除触边裁切轮廓 | 不把轮廓内部每个孔都当成独立视图；超过24个候选不截断后强行配对 |
| 外观指纹 | 保持纵横比缩入112像素长边、居中到128×128；区分填充轮廓和内部墨迹 | 用于建立对应；不直接作为差异证据，后续缩放须独立通过门槛 |
| 子图候选相似度 | 两轴新/旧尺寸比均在0.65～1.5，相对纵横比偏差≤0.25；内部墨迹充分时，0.25×轮廓IoU＋0.75×内部墨迹相似度，否则轮廓与完整墨迹各占0.5 | 墨迹相似度由双向距离变换计算；不是模型推理出的部件身份 |
| 子图唯一性 | 分数≥0.80；两侧均领先其他候选≥0.06 | 外观相同、竞争接近时拒绝强配，不用位置打破歧义 |
| 平移配准 | 近乎一致时接受原位；唯一可比大矩形用中心平移；否则尝试相位相关与 ORB 特征平移共识 | 缩放另有独立门槛；矩形平移分支不等于残差足够小 |
| 等比绘图缩放 | 比例范围0.65～1.5，变化至少2%，两轴比例相对误差≤1.5%，内部墨迹相似度≥0.80，变换后未对应墨迹比例≤0.30 | 只使用一个缩放系数；近似等比允许栅格量化偏差，不执行非等比形变；文字/线条残差仍独立比较 |
| 栅格微调 | 等比系数微调最多0.004且受长边像素限制；平移微调最多±0.5像素 | 仅减少量化误差，不以任意变形拟合新图 |
| 通用配准门槛 | 相位响应≥0.12；ORB 平移内点至少5个；候选位移不超过区域宽/高35%，残差比例改善＞0.025；最终残差比例≤0.45，原位分支还须≤0.12 | 这是非矩形通用分支；不能把它当作所有配准路径的统一置信度 |
| 独立对齐/尺寸诊断 | 对应关系及绘图大小用于选择独立对齐；可选提示保存已接受变换在旧视图中心处的位移及新/旧宽高比例 | 平移/绘图缩放不计内容变化；绘图大小与尺寸标注、实物大小不是一回事 |
| 残差与框 | 对称比较两侧墨迹，邻域容忍约0.3pt（至少1像素）；连通域过滤噪声后按实际像素支持区域出框 | 闭运算可合并邻近残差，但不以填充后的假像素作证据；每侧每类最多24框 |
| 文字/图形分流 | 依据 CU word source 建文字掩膜，掩膜内外残差分别报告 | 没有 OCR 文字框时，文字也可能出现在图形通道 |
| 矩形左缘长线 | 在主矩形左侧约15%内部寻找纵向覆盖≥85%的墨迹列，合并相邻列为线条 | 排除短条码类线段；只框无法对应的实际线段，不解读工艺 |

子图机制是对父区配准不足的补充：按可靠对应的视图核对各自内容，保留其余父区残差。
相对顺序检查用于选择独立对齐路径；位置提示与设计内容比较分开，不把交换当内容修改。
未可靠独立对齐的子图不会从父区残差中剔除。

#### 输出如何追溯到实现

| 模块 / 入口 | 负责内容 |
|---|---|
| `cu_diff\client.py` | CU 请求、Entra 身份、缓存、异步续查及请求级模型映射 |
| `cu_diff\compare.py` / `compare_documents` | 字段、BOM 角色和 OCR 对应；原文/解释/格式分类 |
| `cu_diff\table_diff.py` / `refine_bom` | 从原始 CU 表格细化变化列 |
| `cu_diff\evidence.py`、`cu_diff\web_evidence.py` | source 解析、限定归一化和 Web 坐标映射 |
| `cu_diff\graphics.py` / `compare_graphics` | 父图形配对、同尺度渲染、配准、残差、长线规则、覆盖与证据 |
| `cu_diff\subviews.py` / `extract_subviews`、`pair_subviews`、`order_reversals` | 子图分段、外观唯一配对；内部顺序检查仅辅助独立对齐 |
| `cu_diff\web.py` / `Store.run_job` | 串联 CU/缓存、文字比较、图形比较，发布结果并记录作业审计 |
| `cu_diff\static\app.js` | 按类别筛选、文档身份/旧结果防护、框与上下文导航 |

图形条目的 `graphics.subview` 记录两侧子图编号、配对得分和领先次佳的差值及绘图大小。
不以子图顺序反转作为内容结论。可选条目的 `translation_pt={dx,dy}` 是纸面中心位移，
`scale_ratio={x,y}` 是观察到的新/旧宽高比例；`alignment.scale_ratio` 是实际采用的
等比系数。`optional_transformation=true`、`evidence_role=transformation_frame`
明确标记整视图范围，而非变化像素。
`locations` 保留本侧实际证据，`context_locations` 只负责定位上下文。
`counterpart_locations` 是单侧残差的对侧映射位置，带
`evidence_role=projected_counterpart`、`from_side`、`source_location_index`；
`counterpart_source` 记录配准参数和两侧裁切原点。前端只将满足来源/配准条件的
投影画为红色虚框，不按上下文区域猜测框；详情分别列出实际残差框与对应定位框数量。
投影使用各侧准确的 `source.render_scale`、页尺寸及裁切像素原点，支持等比缩放正反向映射；
仅裁剪到目标页界限，不改变原图、实际残差统计或差异候选数量。
`graphics_coverage.subview_matching` 记录两侧候选、唯一对应、未对应及独立替换残差数量，
`transformation_candidates` 单列平移/缩放提示数量，`design_content_items` 单列内容候选；
两种计数不能相加当作工程变更数。`warnings`、未显示区域数和失败状态也必须一起审阅。

纯离线CLI（没有CU布局时自动全页扫描；无需Azure认证）：

```powershell
.\.venv\Scripts\python -m pip install -e ".[graphics]"
.\.venv\Scripts\python -m cu_diff.cli graphics `
  --old C:\approved-input\old.pdf --new C:\approved-input\new.pdf `
  --output C:\local-results\graphics
```

如复用已有CU布局，可另外提供 `--old-response` / `--old-metadata` 和对应的
`--new-response` / `--new-metadata`。metadata中的输入SHA256必须与PDF字节一致，否则拒绝。
输出 `graphics.json` 和中文候选表 `graphics.zh.md`，包含来源和覆盖信息，仍只能本地保存。
CLI 默认不输出可选变换条目；追加 `--include-translation`、`--include-scaling`
可分别纳入对应提示。引擎 `include_transformations` 开关不改变内容比较结果，
可选条目追加在内容条目之后；Web 预先请求这些提示供前端复选框即时筛选。

### BOM列级差异与格式误报

配对BOM行后，使用同侧原始CU表格单元格的来源坐标关联行，并核对单元格文字与
结构化整行原文一致。按明确的表头别名对应列，而非直接比较第几列；数量/单位合列
和拆列合并为同一语义字段。红框仅使用发生变化的单元格原始source，详情逐列展示
旧值→新值；其余列保留为上下文但不标红。数量改变而单位未变时，新侧独立单位列不标红。
纯BOM行重排只框行号；伴随材料变化时单独列出两项，不把组件重排当作替换。

若无CU表格、合并单元格不能可靠解释、对应行不唯一、表头无法完整配对或单元格
文字与整行提取冲突，则明确显示“无法细化”，**不会退回整行差异红框**。列坐标和
原始表头/单元格保留在JSON的 `cell_comparison`；CU未给单元格独立置信度时不编造数值。
这仍是提取值差异，不排除OCR字符误读，也不检测全部几何变化。

明确标注为标题日期/设计/审核字段的合法年月日，仅分隔符旁空格不同，归为
`formatting_only`，不计原文变更；非法日期、真实日期变化、料号、尺寸与任意文本不
套用此规则。表格列值相同的数量单位空格/拆列也归为格式项。原文不被修改；
可通过“仅格式差异”查看，默认不画差异红框。没有简单删除全部空格或标点。

### 旋转、缩放与缓存

- PNG 预览和 SVG 红框共享同一页面布局，位置按 CU 页尺寸归一化，CSS缩放/DPR不会
  更改证据坐标。页面图像最大2400像素宽/800万像素，用于审阅而非原矢量下载。
- 带90/180/270度旋转的上传文件保留原件，并生成 `remove_rotation()` 外观保持的
  本地分析副本。先按原始文件hash查找已有CU缓存，逐页核对缓存尺寸，并验证旋转规范化
  前后本地渲染像素hash一致（最多200万像素的校验图），才复用其坐标。不是仅凭宽高
  相同判断旋转/裁剪坐标正确。否则CU与预览使用同一零旋转副本，不猜测旋转变换。
  保存副本不生成随机PDF ID，重复上传可复用同一规范化缓存。普通零旋转PDF不改字节。
- `--cache-dir` 可指向已有 CLI `cache` 目录；命中缓存不会再次提交分析请求。
  `usage` 是原分析历史用量，不能当作缓存命中时新增计费。
- 不传 `--allow-azure-upload` 时是**只读缓存模式**：仍需 Entra 对已有 analyzer
  做只读核对；缓存未命中会明确失败，不自动产生计费上传。已提交异步操作可续查。
- 单个服务进程仍串行处理完整分析作业、最多排队4个；作业内仅两侧CU可并行，
  使用同一客户端的缓存键锁避免重复提交和写入冲突。
  **不要让多个服务进程/CLI并发写同一缓存目录**；当前未实现跨进程锁。

复核新增调用与计费时，应把三个问题分开：

| 问题 | 核对方式 |
|---|---|
| 本轮是否重新提交 CU 分析？ | 查看当前作业审计或 `api-events.json` 的 analyze POST；只看到成功结果不足以证明缓存命中 |
| usage 是本次产生还是缓存中的历史值？ | 同时核对 `cache_hit`、输入 hash、analyzer/模型版本和操作记录；缓存命中不能把历史 token 重算为本次新增 |
| 实际花费是多少？ | 保留 CU 返回的页面、contextualization 和各模型 token 使用量；未返回的量标“待核对”，金额以 Azure 账单为准 |

历史排障曾因旋转规范化副本改变输入字节而产生额外分析，不能把后续缓存复用或
本地图形“零新增分析调用”扩大成整个项目“零新增计费”。
调试图形规则优先用离线 `graphics`；验证真实 Web 缓存路径时省略 `--allow-azure-upload`，
防止缓存未命中变成未经计划的付费重跑。运行模式和审计结果应与本次报告一起保存。

### 每轮用量与费用

图片下方分为“证据详情 / 分析耗时 / 用量与费用”三个独立标签页，可用左右方向键切换。
“分析耗时”显示**本轮分析耗时**：总耗时、其中的排队时间，以及关键步骤的实际执行时间、
进行中/完成/失败状态。使用服务端单调时钟，运行中随任务查询刷新；失败也保留已经耗费的时间。
步骤按执行顺序以“步骤序号 / 步骤 / 耗时”三列表格显示；子步骤采用1.1、1.2等编号，
状态与并行说明放在步骤列，耗时列右对齐。子步骤不重复计入总耗时。
步骤包括分析器准备、两侧全页CU、全页模型配对、高清裁剪、两侧局部CU、细粒度文字核对、
图形模型复核、文本语义配对、本地表格/图形对比和结果整理。重复步骤分段记录，不与父阶段重复累计。
两侧CU显示为一个实际墙钟阶段，下方保留各侧独立耗时和状态，并标注是否并行。
并行子步骤时间会重叠，**不能相加当作阶段或总耗时**；顶层阶段仍不重叠。
缓存命中显示本轮读缓存和处理的实际耗时，不使用缓存响应中保存的历史Azure服务耗时。
没有计时字段的旧结果显示无数据或“未提供”，不猜测为零；更换文件或开始下一轮会清空上一轮统计。
全页CU、局部CU、全页模型配对、词级核对、图形复核逐次列出，运行中更新；
后续步骤失败也保留此前用量。更换文件会清空界面中的旧统计，本地作业审计仍保留记录。
“用量与费用”仅显示当前作业的用量和金额估算，不再混入耗时内容，也不是订阅账单。

费用区依次显示**本轮总费用估算 → 三个分项 → 费用细节**：

| 分项 | 包含的计量 |
|---|---|
| CU 分析费用 | 文档页面提取、适用的上下文处理 |
| CU 内部模型费用 | CU 内部生成模型的token，如旧工程字段模式的GPT-5.4 |
| 分析模型费用 | 用户本轮选择的Astra/Luna直接调用 |

总额与分项均由后端按本轮新增调用计算，不在浏览器累加原始token、重复计量或候选价格。
仅有可信轻量提取来源且确实未启用生成计量时，CU内部模型标为“不适用/未启用”，
不再要求不存在的内部模型token；实际报告的其他计量仍保留，不因为轻量模式而忽略。
来源不明、失败或真正缺失的用量仍保持待核，不虚构零费用。
价格档位不能确认时显示场景范围；缺少可靠拆分的旧报告显示“未提供分项”，不自行补零。

本地缓存/恢复引用的费用不计入本轮总额与三个分项，记录折叠在费用细节之后。
原始历史参考仍保留在审计和复用明细内，不把历史花费重新收费，也不改写原报告；
同一缓存引用不重复计入历史审计合计。复用明细中的参考费用按配置价格重新估算，
不代表原执行日期的实际账单。
服务端缓存输入不是本地缓存命中：前者仍按相应token单价计费，后者不产生新的分析提交。
续查以前提交的异步操作归历史参考；未知或失败请求可能已经计费，不能显示为免费。
模型推理token已包括在输出token中，不再相加；缓存写入token单列，计费口径未核实时不猜。

`pricing` 配置不参与CU/模型缓存指纹，更新单价不需要重跑收费请求。默认不配置单价时，
仍展示实际返回的用量，未知费用不会填零。可以在本地配置中启用已公开核对的价格快照：

### 本地隔离与生命周期

每个浏览器会话使用 HttpOnly/SameSite cookie、CSRF令牌和独立随机文件标识，不能访问
另一会话的文档/作业。上传文件名仅作显示，不参与磁盘路径。更换/删除任一文件立即失效
旧结果；若 Azure 请求已发出，无法撤销已发生的费用，旧作业结束后也不会重新展示旧框。
最多16个本地会话；闲置24小时的会话在后续请求/启动时清理，不是独立后台清理服务。

`--data-dir` 下的 `web-session-<随机值>` 保存上传原件/旋转副本和作业审计，不记录
客户文字到控制台。更换文件后不再被当前作业使用的旧PDF会清除。**CU缓存单独长期保留**，
不会随浏览器关闭删除。清理时先停止服务，再在资源管理器中删除指定会话目录；
若要清理计费缓存，针对所选文档的 `<cache-key>.response.json`、
`<cache-key>.metadata.json` 及操作记录逐一删除。删除缓存意味着下次可能重新计费。
不要删除或覆盖原始客户文件。所有运行数据应放在仓库外，或已忽略的 `local\` / `output\`。

当前是单机审阅工具，服务随启动它的进程/会话退出而停止；终端内可用 Ctrl+C 停止。
保留了标准 WSGI `create_app` 工厂，便于以后适配 Azure App Service；**本轮没有部署**。
公网部署前仍需组织认证、跨进程作业队列、存储策略和额外运行隔离，不应直接改成
`0.0.0.0` 暴露此本地模式。

真实文件另做本地端到端复核，不能以合成用例代替。复核清单：

- 明确 old/new 顺序，记录原件 hash；检查真实页面内容，而非只比较宽高或文件名。
- 对旋转 PDF，在两侧可识别的 BOM 文字、标题栏和图形子图处核对来源；
  再检查规范化预览和原件渲染是否一致，避免重复旋转。
- 核对跨位置对应的是同一外观视图：纯平移/绘图缩放默认隐藏，实际内容变化仍保留；
  勾选对应复选框后才显示可选视图提示/黄色范围框，取消后列表、框和详情一起消失。
- 在适应宽度、150%、200%及不同 DPR 下量测框与预览；检查换文件后旧框失效。
- 重上传原件并验证 hash 缓存再次命中；核对当前作业的 analyze POST 和 usage 归属。
- 保存剩余不确定项和覆盖限制；没有框不等于无变化，候选数量不等于真实变更数量。

已有授权真实文件验证不等于多客户、多图种评测。若要给出精确率/召回率，需要单独建立
经人工签核、具有明确匹配及变化标注的参考集，按文本、表格、图形内容分别评估，
并将纯平移/交换作为不应误报的负例；
当前项目没有这样的已验证指标。
