# 工程图 CU 提取与证据差异

Python CLI 与本地 Web 审阅台，使用 **Azure Content Understanding GA `2025-11-01`** 对两份原始 PDF
分别进行全页 OCR/layout 与领域结构化提取，再在本地保守配对。不是仅凭 LLM 看图总结。
支持 BOM、插头认证印字、线材印字、包装/标签、尺寸公差、备注及图框字段。
本地 Web 另有独立图形候选通道：基于原始PDF渲染和CU布局来源，不额外调用生成模型。
文件名/料号不用于推断新旧顺序，必须由调用者指定。

**当前比较口径：只比较设计内容，不将视图在纸面上的平移、左右交换或顺序反转作为差异。**
跨位置配对与平移对齐仍在内部执行，用于排除排版影响；移动后实际改变的文字、线条和尺寸
仍要比较。不能可靠配对/对齐时明确待核，不以“忽略位移”为由静默跳过内容。

客户原文、真实料号、截图、差异坐标、资源配置和调用用量明细仅保留在本地证据文件。

## 隐私与前提

- 只向明确授权的现有 Azure CU 资源上传输入，不使用第三方解析服务。
- **客户 PDF、原文、图片、报告、原始响应、凭据不得提交到 GitHub，包括私有仓库。**
  默认 `output\` 和 `local\` 被忽略。建议将实际结果写在仓库外的持久本地目录。
  `.gitignore` 不是安全边界，提交前必须检查暂存内容。
- Azure CLI 已 `az login`，当前身份有 CU 数据平面及自定义 analyzer 创建权限。
  使用内存中的 Entra token，不读取/打印 API key，不保存 token。
- 先确认资源地域、CU `processing_location`（如 `geography`）和模型部署 SKU 的数据边界。
  **资源在某地域不意味着 GlobalStandard 模型处理仅发生在该地域。**
- 只创建有 schema hash 名称的自定义 analyzer；不创建 Azure 资源/模型部署，
  不修改共享 defaults、容量或模型。需在使用前取得该操作的授权。
- `config.example.json` 中 deployment_versions 必须记录实际模型版本和 SKU；
  模型升级后更新它，避免误复用缓存。实际配置存 `local\config.json`，不含密钥。

## 运行（PowerShell）

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -e .
New-Item -ItemType Directory -Force local
Copy-Item config.example.json local\config.json # 填写真实配置

.\.venv\Scripts\python -m cu_diff.cli diagnose --config local\config.json

.\.venv\Scripts\python -m cu_diff.cli extract `
  --config local\config.json `
  --old C:\approved-input\old.pdf --new C:\approved-input\new.pdf `
  --output C:\local-results\drawing-diff --allow-azure-upload

.\.venv\Scripts\python -m cu_diff.cli compare `
  --old C:\local-results\drawing-diff\old.response.json `
  --new C:\local-results\drawing-diff\new.response.json `
  --output C:\local-results\drawing-diff
```

`extract` 保持 OCR 开启，即使 PDF 有少量原生文本；工程图大量文字可能是矢量轮廓。
同一输入 SHA256 + 完整 analyzer + API + 模型映射/版本 + 处理边界缓存已完成结果。
异步操作先保存地址，超时重跑会续查该作业，不会自动重新发起计费请求。
失败作业保留其记录并明确报错；要重新计费尝试，先调查错误，再有意识地移走对应
`cache\*.operation.json`。不能把空结果当成“无变更”。

每次请求显式传 `modelDeployments`，不修改资源默认映射。响应中的真实 usage、
延迟和 HTTP 状态本地保存；不凭 token 估算金额。CU 提取、contextualization 和
Foundry 模型分别计费，最终金额需以 Azure 账单为准。

CU 在创建 analyzer 阶段会验证模型默认映射，早于请求级 override。
因此 analyzer 使用已有 `prebuilt-analyzer-completion` 别名，分析请求将该别名
显式映射到配置指定的模型部署；绝不依赖其可能指向其它模型的资源默认值。
实际所选模型及完整映射保留在 metadata 中，最终 usage 也应核对模型名称。

`diagnose` 只读检查 CU 实际 supportedModels 和默认映射，不上传文件。
存在 Azure OpenAI 部署并不等于 CU 支持该模型。`extract` 遇到不支持的模型会在
创建 analyzer/上传文件之前停止；不会偷偷换成其它模型。

## 输出与证据

| 文件 | 内容 |
|---|---|
| `old.response.json` / `new.response.json` | 完整 CU 字段、OCR、表格、图形、source/confidence、usage |
| `*.inspection.json` | SHA256、物理页尺寸、原生词/位图/矢量路径数量 |
| `*.metadata.json` | 输入 hash、analyzer/schema、模型版本、操作地址与实际耗时 |
| `api-events.json` | 当前运行的 HTTP 状态、请求 ID、延迟；可能含服务错误，按敏感结果保管 |
| `comparison.json` | 原文与保守标准化值、配对方法、提取/匹配不确定性、覆盖计数、OCR 辅助差异 |
| `comparison.zh.md` | 中文证据差异表；候选与未配对项必须复核 |

一般原文只做空白和 Unicode NFC 比较归一化；合法标题日期空格、表格数量/单位格式
另有严格限定的例外，见后文。保留原始字符，标准号/料号/尺寸不转数字。
唯一功能角色键优先配对，其余用保守的文字/坐标候选；不把变更后的料号作为身份键。
全量 OCR 是独立遗漏检查通道，不能将其与字段差异计数相加。
保留未配对区域、低置信度的“相同”内容和服务警告；高置信度不是正确率保证。
BOM 先以稳定部件描述而不是位置行号配对，避免行重排造成错配。生成的解释文字
不同但原文一致时，单列 `interpretation_only`，不计为原文修改。

### 小字复核

从原始矢量 PDF 重新渲染，不放大已有低分辨率截图。以 PDF pt（左上原点）指定裁剪：

```powershell
python -m cu_diff.cli crop --pdf C:\approved-input\old.pdf --page 1 `
  --rect 20 30 300 200 --dpi 600 --output C:\local-results\old-crop.pdf
```

生成裁剪 PDF 及 `.mapping.json`。将对应 old/new crop 用同样 `extract` 流程分析，
保留各自映射；CU inch 坐标乘 72 并加 crop 左上偏移才是原页 pt。全页结果必须先运行，
不能只分析预知变更区域。高分辨率裁剪再次提交 CU 属于额外分析，可能新增计费，
应先检查已有缓存并获得授权。本地渲染本身不调用 CU。
现已实现图形残差和子图跨位置配对，但**尚无经标注参考集验证的完整几何检测能力**，
不能将图形候选或生成描述当作已确认的工程变更。

## 分析逻辑详解

### 职责边界与完整流程

CU 负责两份文档各自的提取，不直接给出可信的“旧图对新图最终结论”。
本地代码负责对应关系、比较、证据坐标和候选分类；人工负责确认实际工程意义。
当前并非任意部件的语义识别器，也没有实现完整的“物体—类型—关系”图谱。
以下流程对应 Web；`cli compare` 只比较已提取字段/OCR，
`cli graphics` 则独立运行本地图形比较，两者的输出范围不能混淆。

| 阶段 | 实际处理 | 必须保留的证据或约束 |
|---|---|---|
| 输入与身份 | 显式指定 old/new；检查 PDF、页数、hash，生成即时预览 | 原件只读；不由文件名、料号判断时间顺序 |
| 坐标准备 | 检查页尺寸和旋转；Web 必要时生成外观保持的分析副本 | 原件 hash 与分析副本 hash 分开记录；不能只凭宽高相同复用坐标 |
| 全页提取 | 分别对完整 PDF 获取 OCR、layout、表格、图形区域和领域字段 | 优先缓存；保留完整响应、原文、source、confidence 和警告 |
| 文本配对 | BOM 角色、唯一字段键、受限文字/坐标候选；另做 OCR 行检查 | 提取置信度与配对确定性分开；未配对不自动成为增删 |
| 列级细化 | 把 BOM 字段关联到同侧实际表格行，按表头角色对齐列 | 列文字须与结构化行文字相符；仅变化列提供差异框 |
| 本地图形 | 配对父图形区、拆分子图、跨位置匹配、独立平移与残差比较 | 使用原 PDF 同尺度渲染；不额外调用生成模型 |
| 审阅与输出 | 显示两侧实际来源、设计内容候选、未配对与覆盖限制 | 纯视图位移不出项、不计数、不画框；用户确认前不是签核结果 |

这与“渲染/OCR → 分段 → 对齐 → 理解 → 配对 → 分通道比较 → 验证”的讨论思路一致，
但当前分段仅包括 CU 字段、OCR 行、表格单元格和局部轮廓子图，
不能声称已完成任意图纸的语义原子化。

### 为什么有原生 PDF 文本仍必须 OCR

工程图可能由大量矢量路径组成：看起来像文字，但字体已转成轮廓，原生文本接口只提取出
页码等少量字符。也可能没有任何内嵌位图，但依然需要渲染后识别文字。
因此“能提取出几个词”或“没有图片”均不能成为关闭 OCR 的依据。
细小印字应从原始矢量 PDF 重新渲染复核，不能靠放大低清截图恢复不存在的细节。
OCR 遗漏仍可能影响文本比较和后续图形中的文字掩膜。

### 字段、OCR 与 BOM 怎样建立对应

字段同时保留 `RawText`（提取原文）、`Detail`（生成解释）、类别、区域、键和来源。
一般字段优先采用两侧唯一的 `region + category + key`；重复键不强行一一对应。
BOM 更早采用同区域中唯一的部件描述/角色，重复描述可用唯一且完全一致的行内容消歧，
避免把位置行号或可能变化的料号当成不变的身份。
这里的“角色”来自提取文字的受限解析，不是独立的语义零件检测。

稳定键不能配对时，只在同类别、同 content 范围考虑候选：
有效单一来源框的 IoU（交并比）≥0.65 且文字相似度≥0.55，或同区域非空文字完全一致。
候选必须互为最佳，并在有竞争者时两侧均领先次佳至少0.15；这类回退对应仍标为不确定。
**多个来源多边形不能直接拿一个猜测的大框套用单框几何回退。**
所以两边肉眼相似的字母组，仍可能因分组、生成键或 OCR 字符不同而保持未配对；
这不等于新图新增了该内容。

OCR 是独立的遗漏检查通道，先找同页原文相同的唯一对应，再检查连续2～8行
能否与另一侧一行完全拼接一致。拆并还需阅读顺序、距离、左边界和来源重叠满足约束，
结果为 `reconciled`，而非一次内容修改。它不是任意段落的智能拆并。
剩余行再做保守的几何/文字配对；重复文字或无法定位的内容继续待核。
默认不把字段差异与 OCR 差异相加，以免同一内容重复计数。

BOM 行配对成功后，还必须通过 `table_diff.py` 的单元格核验：
一侧的整行文字与实际表格行吻合，两侧列按表头含义对应，而不是按第几列对应。
例如合成场景中一行包含品名、数量、单位、料号、材料和厂商，只有料号与厂商变化时，
只框这两列。数量与单位在一侧合列、另一侧拆列，不应导致整行或单位列误报。
证据冲突时显示“无法细化”，不再用整行红框伪装列级结果。

### 非文字部件怎样比较，为什么以前漏掉交换

CU 的一个 `figure` 可能包含多个视图、局部放大图、引线和文字，而不是一个部件。
旧的区域比较只估计一组平移：若区域内两个视图分别向相反方向移动，
不可能用同一个平移量同时对齐。出现大面积像素残差或 `visual_uncertain`，
并不表示系统已识别出两个视图交换。

当前增加了子图层。以**合成示例**说明：旧图从左到右是视图 A、B，新图是 B、A。
算法先分别寻找具有可分辨轮廓和内部特征的子图，再比较 A 与各新图候选的外观，
建立旧 A→新 A、旧 B→新 B；不按“旧左→新左”强配。
对应关系唯一时，按各自视图的局部坐标比较内容，而不是比较原纸面位置。
早期版本曾输出位置变化项；现在按设计审阅口径移除它们，不再输出位移/顺序反转
条目、数量或整视图位置框。A、B 只交换位置而内容不变时不产生设计差异。

“不报告位置变化”与“确认内容相同”是两件事：配对指纹可以归一化尺寸以寻找身份，
但正式外观残差保持原物理尺度，不缩放消除绘图大小变化。
子图移动后仍可能有轮廓和标注变化。独立对齐成功后，用子图残差替代父区相同位置的残差；
未覆盖的父区和未可靠对齐的子图仍留待复核，不因找到交换视图就忽略其余内容。
重复或极相似视图不会以位置强行打破平局，无法确认对应时保留待核，而非宣称设计内容一致。
详细阈值及对应实现见后文“图形算法与阈值”。

### 如何解释结果和框

| 分类 | 表示什么 | 不表示什么 |
|---|---|---|
| `modified` | 已配对提取原文不同；BOM 可细化到变化列 | 不是排除了 OCR 错误的工程结论 |
| `relocated` | BOM 角色配对后的印刷行号变化 | 不是纸面几何位移，也不是自动认定替换了部件 |
| `formatting_only` | 合法标题日期空格，或表格列值一致的限定格式差异 | 不是忽略任意空格、标点或尺寸字符 |
| `interpretation_only` | 原文相同但生成解释/身份标签不同 | 不是图纸原文改变 |
| `reconciled` | 满足约束的 OCR 行拆并对应 | 不是新增或删除文字 |
| `unpaired_old` / `unpaired_new` | 本侧有证据，尚未可靠找到另一侧对应 | 不是确认删除/新增，也不是另一侧没有该内容 |
| 历史 `visual_moved` | 当前图形引擎已不再输出；前端也排除旧后端返回的此类条目 | 不进入任何筛选列表、差异计数或证据框 |
| `visual_modified` | 局部墨迹/线条外观残差候选 | 不能推断材料、工艺、功能或真实尺寸 |
| `visual_annotation` | 落在 CU 文字位置掩膜内的残差候选 | 不是可靠的文字语义分类；OCR 掩膜也可能不完整 |
| `visual_uncertain` | 对齐未可靠接受，像素差异只供复核 | 既不是确认修改，也不是“没有变化” |

当前只绘制内容证据框，来自文字/单元格来源或实际残差像素，不绘制整视图位移框。
`context_locations` 仅供导航，不自动画成差异框。
单侧有新增墨迹时允许只在该侧画框，不为了左右对称捏造另一侧证据。
提取 `confidence`、对应 `match.certainty`、启发式 `score` 与配准是否接受是不同信息；
图形没有概率置信度，不把匹配得分换算成“准确率”。
`D...`、`G...` 是当前结果中的显示编号，不是跨版本稳定的部件标识；
新增检测层后编号可能变化，复核应同时保存两侧 hash、原文/位置及配对元数据。

### 讨论中的问题与修正（脱敏归纳）

| 观察到的问题 | 原因 | 当前处理及尚存限制 |
|---|---|---|
| 两侧看起来一样，却显示差异 | OCR 字符/分组或生成键不同；未配对项曾容易被误读为新增 | 未配对单列待核，不凭肉眼相似强行配对；保留两侧独立证据 |
| 怀疑比较了同一份文件 | 相似版式和联动定位不足以证明文件身份 | 显示原件 SHA256、前后端拒绝相同字节、核对返回文档 ID/hash；不同 hash 也不证明每处内容不同 |
| 日期只是间隔不同也报修改 | 纯字符串比较把日期分隔符附近空格当作内容差异 | 仅对明确标题日期字段中的合法日期做限定格式归类 |
| BOM 只有几列变化却整行标红 | 结构化提取的证据粒度是整行，且两侧分列方式可能不同 | 用实际表格 source 做列级细化；无可靠单元格证据则不退回整行红框 |
| 包装图的非文字线条变化遗漏 | 仅字段/OCR 比较没有真正比较图形墨迹 | 增加本地残差、文字掩膜和矩形左缘长线规则；规则不能解释工艺含义 |
| 组合图里视图交换导致错误对应 | 父区域只有一组平移，无法解释相反方向的子图移动 | 保留子图跨位置匹配，先对齐再比较设计内容；交换本身不再输出差异 |
| 旋转图纸重上传时缓存或框不一致 | 原件和规范化副本字节不同；尺寸相同不证明坐标等价 | 原件 hash 优先查缓存，加几何与渲染外观核验；副本保存不生成随机 PDF ID |
| 后端未接入图形能力，前端却有入口 | 静态界面与后端功能状态不同步 | 仅在 `graphics_enabled === true` 时启用；缺失/false 明确不可用，不产生假候选 |

上述修正针对根因，不能据此承诺所有误报已消失。
例如日期格式修正不解决任意 OCR 错字；长线检测不等于完整形状理解；
子图跨位置匹配也不等于能够识别所有语义部件。

### 换成其他两份文档是否适用

这是可复用的工程图对比框架，不依赖客户文件名、真实料号或预先指定的变更坐标；
最适合具有相近版式、明确新旧关系的工程图修订比较。
任意两份无关文档虽然可通过格式校验，但未必存在合理对应，不应把大量未配对当作有效差异报告。

| 输入情况 | 预期表现与边界 |
|---|---|
| 同类图纸的文字、BOM、包装和独立视图修订 | 可复用现有提取与比较链路；仍需人工确认 |
| 大幅改版、图形跨父区移动或页面重排 | 父区按同物理页配对；不保证建立跨区/跨页对应 |
| 扫描图、低分辨率、浅灰细线、遮挡或粘连视图 | 分段、OCR 和残差质量可能下降，可能漏检或出现更多待核项 |
| 任意旋转的单个零件、复杂拓扑或需要判断材料/功能 | 未实现相应语义/几何推理；页面 `/Rotate` 规范化不等于零件旋转识别 |
| 重复且外观相同的多个视图交换 | 图像不足以建立唯一身份，保留不确定性，不强行判定交换 |

更换成未缓存的文档，授权上传模式下会触发新的 CU 分析并可能计费；
只读缓存模式则明确失败。纯本地图形 CLI 不需要 CU，但没有 CU 布局/文字位置时
会回退全页，且不能同样可靠地区分文字标注与非文字外观。

### 本地图形候选（不新增CU分析）

这里的“不新增”仅指本地 `compare_graphics` 阶段；完整 Web 作业之前的 CU 提取
是否新增计费，取决于授权模式和缓存是否命中。

1. 处理整份原始PDF各物理页。优先使用全页CU返回的全部图形来源区域，
   按区域重叠和所引用的原始文字锚点做双向唯一配对，不用生成的图形描述判定变化。
   某页一侧没有可用图形区域时，两侧都回退到该页全幅扫描，明确记录覆盖方式。
2. 在相同物理尺度以默认200dpi灰度渲染，每页最多800万像素；页面大时共同降低DPI，
   不单独缩放某一侧。仅估计刚性平移，不做弹性变形/缩放对齐。
   对复合区域增加**封闭轮廓子图拆分 → 跨位置外观配对 → 独立平移与残差**：
   使用轮廓和内部墨迹建立指纹，不按原位置强制对应。指纹可归一化尺寸，但实际残差
   始终保留相同物理尺度，不将绘图缩放差异抹掉。双向最佳匹配须得分≥0.80，
   且两侧均比次佳高≥0.06；这些是启发式阈值，不是准确率。
   可建立旧左→新右、旧右→新左的对应视图，只报告独立对齐后仍存在的内容残差。
   不输出子图位移/顺序反转项，也不绘制整视图位置框；绘图尺寸变化仍保留供复核。
   重复或无法唯一匹配的视图保留父区域复核，不强行确认交换，也不认定新增/删除。
3. 唯一的大矩形轮廓可作为平移基准，其绘图宽高比变化仍保留。附着引线不要求
   整个连通轮廓仍是四边形，而是校验实际四条直边。矩形左缘长竖线可进一步统计，
   只框未配对的实际线条；不把线数直接解释成封口工艺、材料或实物结构。
4. 对齐后比较各侧实际墨迹残差，抑制小范围锯齿噪声；CU文字位置用于分离含文字
   的标注候选。只在实际出现残差的一侧画框，另一侧可导航到上下文，但不臆造变化框。
   纯平移不报告；不能用缩放对齐抹去真实的轮廓尺寸/比例差异。
5. 缺少可靠对应关系或不能对齐的复杂组合图保留 `visual_uncertain`，仅供复核，
   不假装完成了语义部件识别。成功独立对齐的子图用其局部残差替代父区相同位置的残差；
   其余父区域仍比较，不因找到两幅子图而忽略其他内容。
   子图外14pt上下文中，仅消除能按同一已接受平移逐像素对应的墨迹，避免随视图移动的
   不变标签误报；其他候选轮廓受保护，无法对应的文字和线条仍保留为残差。
   每侧每类最多显示24个残差区域，未显示数量和阈值明确记录。
   每父区最多24个子图候选；超限则跳过该区子图配对，避免截断制造“唯一匹配”。
   子图最小边长14pt，开口/相连轮廓、过小图形、外观近似视图及跨父区/跨页移动仍可能漏检。

图形编号 `G...` 与字段编号 `D...` 分开。详情记录渲染DPI、对齐方法、
变化像素数、归一化原页坐标和限制。匹配分数不是正确率；外观残差框是变化像素的包围区域，
不代表框内所有内容改变。对齐偏移仅作为内部/机器诊断数据保留，不显示为设计差异。
细小/浅灰标记、图形分组错误、页面重排可能漏检，
也不解码条码内容。尺寸标注数值应继续与字段证据结合，不能由示意图宽高推断实物尺寸。
浏览器只有收到后端 `graphics_enabled=true` 才启用图形入口；旧后端缺少此字段时
明确显示未启用，不产生假候选。图形阶段异常会使本轮任务明确失败。

#### 图形算法与阈值

当前方法版本为 `local-graphics-v3`，输出 `comparison_policy=design_content_only`。
以下数值来自实现，用于说明误差容忍和候选选择，
不是经客户参考集校准的精度指标，也不代表已有同名配置项可直接修改。

| 层次 | 当前规则 | 取舍 |
|---|---|---|
| 父区域来源 | CU 全页提取的 figure source；使用引用段落的原文字面锚点，不使用生成描述 | CU figure 不是语义部件；一侧无有效区域或区域数超过32时，两侧同页回退全幅 |
| 父区域配对 | IoU≥0.2，或文字词项 Jaccard≥0.7 且共享至少3个词项；分数为0.65×IoU＋0.35×Jaccard；双向最佳、次佳差值≥0.12 | 不仅按位置，但仍依赖父区对应；子图不会任意跨父区搜索 |
| 同尺度渲染 | 默认200dpi，允许96～300dpi；每页上限800万像素，两侧共同降采样；灰度值＜180为墨迹 | 大页实际 DPI 可能低于请求值；细浅线可能遗漏 |
| 子图候选 | 小尺度闭运算后提取层级轮廓；最小边长14pt；轮廓面积/包围框面积≥0.25；框面积≤父区域比较栅格60%；排除触边裁切轮廓 | 不把轮廓内部每个孔都当成独立视图；超过24个候选不截断后强行配对 |
| 外观指纹 | 保持纵横比缩入112像素长边、居中到128×128；区分填充轮廓和内部墨迹 | 仅配对阶段缩放，不缩放实际差异证据 |
| 子图候选相似度 | 两轴新/旧尺寸比均在0.65～1.5，相对纵横比偏差≤0.25；内部墨迹充分时，0.25×轮廓IoU＋0.75×内部墨迹相似度，否则轮廓与完整墨迹各占0.5 | 墨迹相似度由双向距离变换计算；不是模型推理出的部件身份 |
| 子图唯一性 | 分数≥0.80；两侧均领先其他候选≥0.06 | 外观相同、竞争接近时拒绝强配，不用位置打破歧义 |
| 配准 | 近乎一致时接受原位；唯一可比大矩形用中心平移；否则尝试相位相关与 ORB 特征平移共识 | 只估计平移，无缩放、仿射或弹性变形；矩形分支不等于残差足够小 |
| 通用配准门槛 | 相位响应≥0.12；ORB 平移内点至少5个；候选位移不超过区域宽/高35%，残差比例改善＞0.025；最终残差比例≤0.45，原位分支还须≤0.12 | 这是非矩形通用分支；不能把它当作所有配准路径的统一置信度 |
| 独立对齐/尺寸诊断 | 中心差异只用于判断是否需独立对齐；宽或高同时变化＞1pt且比例＞2%时记录绘图尺寸变化 | 位移和顺序不计差异；绘图大小与尺寸标注、实物大小不是一回事 |
| 残差与框 | 对称比较两侧墨迹，邻域容忍约0.3pt（至少1像素）；连通域过滤噪声后按实际像素支持区域出框 | 闭运算可合并邻近残差，但不以填充后的假像素作证据；每侧每类最多24框 |
| 文字/图形分流 | 依据 CU word source 建文字掩膜，掩膜内外残差分别报告 | 没有 OCR 文字框时，文字也可能出现在图形通道 |
| 矩形左缘长线 | 在主矩形左侧约15%内部寻找纵向覆盖≥85%的墨迹列，合并相邻列为线条 | 排除短条码类线段；只框无法对应的实际线段，不解读工艺 |

子图机制是对父区配准不足的补充：父区已经可靠对齐、子图没有独立移动或顺序反转时，
继续保留父区内容比较。相对顺序检查仅用于选择独立对齐路径，不作为业务变化输出。
未可靠独立对齐的子图不会从父区残差中剔除。

### BOM列级差异与格式误报

配对BOM行后，使用同侧原始CU表格单元格的来源坐标关联行，并核对单元格文字与
结构化整行原文一致。按明确的表头别名对应列，而非直接比较第几列；数量/单位合列
和拆列合并为同一语义字段。红框仅使用发生变化的单元格原始source，详情逐列展示
旧值→新值；其余列保留为上下文但不标红。数量改变而单位未变时，新侧独立单位列不标红。
纯BOM行重排只框行号；伴随材料变化时单独列出两项，不把组件重排当作替换。

若无CU表格、合并单元格不能可靠解释、对应行不唯一、表头无法完整配对或单元格
文字与整行提取冲突，则明确显示“无法细化”，**不会退回整行差异红框**。列坐标和
原始表头/单元格保留在JSON的 `cell_comparison`；CU未给单元格独立置信度时不编造数值。
这仍是提取值差异，不排除OCR字符误读，也不检测全部几何变化。

明确标注为标题日期/设计/审核字段的合法年月日，仅分隔符旁空格不同，归为
`formatting_only`，不计原文变更；非法日期、真实日期变化、料号、尺寸与任意文本不
套用此规则。表格列值相同的数量单位空格/拆列也归为格式项。原文不被修改；
可通过“仅格式差异”查看，默认不画差异红框。没有简单删除全部空格或标点。

### 旋转、缩放与缓存

- PNG 预览和 SVG 红框共享同一页面布局，位置按 CU 页尺寸归一化，CSS缩放/DPR不会
  更改证据坐标。页面图像最大2400像素宽/800万像素，用于审阅而非原矢量下载。
- 带90/180/270度旋转的上传文件保留原件，并生成 `remove_rotation()` 外观保持的
  本地分析副本。先按原始文件hash查找已有CU缓存，逐页核对缓存尺寸，并验证旋转规范化
  前后本地渲染像素hash一致（最多200万像素的校验图），才复用其坐标。不是仅凭宽高
  相同判断旋转/裁剪坐标正确。否则CU与预览使用同一零旋转副本，不猜测旋转变换。
  保存副本不生成随机PDF ID，重复上传可复用同一规范化缓存。普通零旋转PDF不改字节。
- `--cache-dir` 可指向已有 CLI `cache` 目录；命中缓存不会再次提交分析请求。
  `usage` 是原分析历史用量，不能当作缓存命中时新增计费。
- 不传 `--allow-azure-upload` 时是**只读缓存模式**：仍需 Entra 对已有 analyzer
  做只读核对；缓存未命中会明确失败，不自动产生计费上传。已提交异步操作可续查。
- 单个服务进程串行处理分析作业、最多排队4个，避免同进程重复写同一缓存。
  **不要让多个服务进程/CLI并发写同一缓存目录**；当前未实现跨进程锁。

复核新增调用与计费时，应把三个问题分开：

| 问题 | 核对方式 |
|---|---|
| 本轮是否重新提交 CU 分析？ | 查看当前作业审计或 `api-events.json` 的 analyze POST；只看到成功结果不足以证明缓存命中 |
| usage 是本次产生还是缓存中的历史值？ | 同时核对 `cache_hit`、输入 hash、analyzer/模型版本和操作记录；缓存命中不能把历史 token 重算为本次新增 |
| 实际花费是多少？ | 保留 CU 返回的页面、contextualization 和各模型 token 使用量；未返回的量标“待核对”，金额以 Azure 账单为准 |

历史排障曾因旋转规范化副本改变输入字节而产生额外分析，不能把后续缓存复用或
本地图形“零新增分析调用”扩大成整个项目“零新增计费”。
调试图形规则优先用离线 `graphics`；验证真实 Web 缓存路径时省略 `--allow-azure-upload`，
防止缓存未命中变成未经计划的付费重跑。运行模式和审计结果应与本次报告一起保存。

### 本地隔离与生命周期

每个浏览器会话使用 HttpOnly/SameSite cookie、CSRF令牌和独立随机文件标识，不能访问
另一会话的文档/作业。上传文件名仅作显示，不参与磁盘路径。更换/删除任一文件立即失效
旧结果；若 Azure 请求已发出，无法撤销已发生的费用，旧作业结束后也不会重新展示旧框。
最多16个本地会话；闲置24小时的会话在后续请求/启动时清理，不是独立后台清理服务。

`--data-dir` 下的 `web-session-<随机值>` 保存上传原件/旋转副本和作业审计，不记录
客户文字到控制台。更换文件后不再被当前作业使用的旧PDF会清除。**CU缓存单独长期保留**，
不会随浏览器关闭删除。清理时先停止服务，再在资源管理器中删除指定会话目录；
若要清理计费缓存，针对所选文档的 `<cache-key>.response.json`、
`<cache-key>.metadata.json` 及操作记录逐一删除。删除缓存意味着下次可能重新计费。
不要删除或覆盖原始客户文件。所有运行数据应放在仓库外，或已忽略的 `local\` / `output\`。

当前是单机审阅工具，服务随启动它的进程/会话退出而停止；终端内可用 Ctrl+C 停止。
保留了标准 WSGI `create_app` 工厂，便于以后适配 Azure App Service；**本轮没有部署**。
公网部署前仍需组织认证、跨进程作业队列、存储策略和额外运行隔离，不应直接改成
`0.0.0.0` 暴露此本地模式。

实现提交 `b19fce4` 的历史验证快照为 **138 项测试通过**，包含字段/BOM/日期、
缓存与后端、图形引擎和 Chromium 回归；这不是每个后续版本自动继承的通过证明。
子图合成用例覆盖不同视图交换、单个移动、移动同时改形状/文字、重复外观拒绝强配、
原图不变、统一平移不重复计数、绘图缩放不被抹掉、页面边框/旋转、未覆盖墨迹和候选超限。
当前内容优先版本把纯平移/交换改为“零内容差异”断言，并检查随视图移动的不变标签不误报、
附近标签真实修改不被消除、移动后新增线条保留；前端兼容测试保证历史移动项不显示、不计数。
浏览器用例还检查跨位置两侧框、缩放/DPR、能力未启用、替换文件清空和原有列级行为。

真实文件另做本地端到端复核，不能以合成用例代替。复核清单：

- 明确 old/new 顺序，记录原件 hash；检查真实页面内容，而非只比较宽高或文件名。
- 对旋转 PDF，在两侧可识别的 BOM 文字、标题栏和图形子图处核对来源；
  再检查规范化预览和原件渲染是否一致，避免重复旋转。
- 核对跨位置对应的是同一外观视图：纯位置变化不出项，移动后实际内容变化仍出项；
  不再输出 `visual_moved`，只绘单元格/残差证据，保留仅导航上下文。
- 在适应宽度、150%、200%及不同 DPR 下量测框与预览；检查换文件后旧框失效。
- 重上传原件并验证 hash 缓存再次命中；核对当前作业的 analyze POST 和 usage 归属。
- 保存剩余不确定项和覆盖限制；没有框不等于无变化，候选数量不等于真实变更数量。

已有授权真实文件验证不等于多客户、多图种评测。若要给出精确率/召回率，需要单独建立
经人工签核、具有明确匹配及变化标注的参考集，按文本、表格、图形内容分别评估，
并将纯平移/交换作为不应误报的负例；
当前项目没有这样的已验证指标。
